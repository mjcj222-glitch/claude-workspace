# 잔향 회로 시각·연출 개선 보고

## 방향과 변경

어두운 청록색 유리 온실에 떠 있는 독자적 수정 생명체를 중심으로 재구성했다. 외부 이미지·폰트·패키지 없이 SVG 보스, 원근 골조, 유리 패널, 보석 타일, 회로 프레임, 스킬 문양을 직접 작성했다. 데스크톱은 보스와 기술자/보드를 나란히 배치하고, 360px에서는 보스 장식을 130px 높이로 제한했다.

규칙 엔진은 변경하지 않았다. 선택 강조 → 최대 90ms 간격 범위의 순차 소거 → ID 기반 개별 낙하를 기존 400ms 해소 안에 배치했다. 시각 효과는 별도 effects.mjs에 분리하며 게임 난수를 사용하지 않는다. 입자는 최대 100개, 장식은 pointer-events:none, 오디오는 없다. reduced-motion이면 입자와 이동 애니메이션을 생략한다.

실제 제거된 폭탄에만 충격파, 실제 잔향 발동에만 연결선을 그린다. 큰 일반 묶음을 폭탄처럼 표시하지 않는다. 피해 숫자는 턴 종료의 실제 보스 HP 감소와 탭의 피해 적립을 구분하고, 회복 및 침식 피해도 별도 문구로 표시한다. 과충전은 금빛 회로 테두리와 메시지, 승패는 구분된 결과 문양을 사용한다. 마지막 타격 후 기본 모션에서는 320ms를 추가로 보여 준 뒤 결과창을 연다. 전투 진행 중의 입력 잠금은 기존 400ms이며, 남은 입자는 입력을 차단하지 않는다.

- 모듈판과 standalone판: 360px·1280px reduced-motion에서 튜토리얼/키보드/연속 입력/승리/패배/재시작 통과. 360px 기본 모션에서는 실제 터치 포인터 탭으로 전체 전투를 진행했다. `polish-browser_check.log`, `polish-standalone_check.log`.

- `after-polish-360.png`, `after-polish-1280.png`, `echo-360.png`를 실제 이미지로 열어 시각 검수했다.

## 미검증·한계

- 실물 모바일 GPU 성능/배터리/프레임률, Safari/Firefox, 스크린리더 사용자 검수는 하지 않았다. 입자 상한은 성능 측정을 대체하지 않는다.
- 드래그 취소는 마우스로 검사했다. 실제 터치 스크롤 및 pointercancel 전체 흐름은 미검수다.
- file:// 직접 실행은 이전에 관리 정책 ERR_BLOCKED_BY_ADMINISTRATOR로 거부되어 재시도하지 않았다. 독립 HTML의 route 검사를 file:// 성공으로 표현하지 않는다.
- 사람의 타격감·재도전 의향·플레이 시간 평가는 아직 없다. 자동 테스트 통과를 재미 입증으로 간주하지 않는다.
- 수동 배포·main 병합·Vercel 연동 변경은 하지 않았다. 기존 자동 연동 상태를 공개 게임 배포 성공으로 주장하지 않는다. PR은 draft 유지.
