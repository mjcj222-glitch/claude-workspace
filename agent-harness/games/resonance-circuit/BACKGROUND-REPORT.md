# 전투 배경 가시성 수정

기준 `cbefbddac88da0a7e8eb6fab974d267a9bd6acb9`. 엔진·스킬·패널·저장 규칙과 기존70개 테스트는 변경하지 않았다.

## 그림과 레이아웃

승인 원본940×1672 PNG를 직접 확인했다. 실제 전투 일러스트의 `x0,y68,width940,height492` 영역을 가로 폭에 비례해 표시한다. 원본 위의 체력바와 아래 보드는 포함하지 않는다. 해당 영역 좌상단에만 남는 기존 UI 배지 끝부분은 CSS clip-path의 작은 홈(x14.5–24%, y0–4.1%)으로 가리고 온실색 배경으로 연결한다. 이 부분에는 캐릭터가 없다. 원본 PNG는 바꾸지 않았다.

얼굴만 cover 확대하던 좁은 표시를 없애고, 꽃왕관·얼굴·펼친 머리카락·몸통·양발과 온실 배경이 함께 보이도록940:492 비율을 유지했다. HUD는 전투 영역의 위30px/아래26px 여백에 배치해 얼굴과 발을 가리지 않는다. 피격 애니메이션은 기존처럼 `.enemy.hit .concept-boss`에만 적용해 HUD나 퍼즐을 흔들지 않는다.

360/390/1280 화면의 실제 그림 높이는 약178/194/218px, HUD 포함 전투 영역은 약234/250/274px다. 기본 상태·덩굴 안내·무지개 안내 모두 같은 그림 높이다. 기존 패널 안내의 얇은 그림 축소 규칙을 덮어썼다. 보드 타일40/44px와 기존 스킬 카드 크기를 유지했다.

## 스크롤의 교환 관계

모든 버튼을 한 화면에 압축하지 않았다. 캡처 기준 문서 전체 높이는 다음과 같다.

| 뷰포트 | 기본 | 덩굴 안내 | 무지개 안내 |
|---|---:|---:|---:|
| 360×800 | 988 | 1013 | 998 |
| 390×844 | 1042 | 1066 | 1051 |
| 1280×900 | 1081 | 1103 | 1088 |

하단 스킬/과충전/설정 접근에 약181–222px 세로 스크롤이 필요하다. 그림을 보여 주는 대신 모든 정보를 한 화면에 유지하지 않는 선택이다. 스크롤하여 하단을 조작하는 동안 상단 그림이 화면 밖으로 나가는 것은 정상이며 고정 배경으로 퍼즐 뒤에 겹치지는 않는다.

시작·이어하기·새 전투·재도전은 상단 그림에서 시작한다. 타일 확정 후와 도움말 닫기에서는 `focus({preventScroll:true})`를 사용한다. 방향키는 대상 타일이 화면 밖일 때만 가장 가까운 위치로 스크롤하므로 키보드 접근을 유지한다. 일반 입력마다 상단으로 되돌리는 처리는 없다.

## 검증과 증거

신규 `background_check.py`: 구현 전 좁은 그림 높이 검사 실패(`background-before.log`, 종료1). 수정 후3해상도×기본/두 패널 안내9화면에서 비율·높이 불변·시작 스크롤0·방향키·도움말 복귀의 스크롤 유지·가로 넘침 없음·타일 터치 크기·JS 오류 없음을 검사했다. `background-browser.log` 성공.

실제 `background-stage-{1,2,3}-{360,390,1280}.png`를 생성했다. 세 해상도의 기본 화면과 각각의 안내 화면을 직접 열어 꽃왕관/얼굴/몸통/발 가시성을 확인했다. 전체 페이지 캡처이므로 스크롤 없이 한 화면에 전부 보인다는 뜻은 아니다.

기존 레이아웃/스킬 검사에서 과충전 버튼이 반드시 뷰포트 안에 있어야 한다는 조건은 이번 요청에 맞춰 충분한 버튼 높이와 스크롤 접근 가능 조건으로 수정했다. 규칙 검사를 완화하지 않았다.

검증 로그: `background-unit.log`(70개 규칙), `background-layout.log`, `background-skills.log`, `background-panels.log`, `background-art.log`, `background-campaign.log`(360px 기본모션 독립 HTML 전체3전투).

변경은 앱의 포커스 처리·CSS·에셋 manifest의 표시 좌표, 브라우저 검사·문서·캡처와 재생성한 독립 HTML/ZIP이며 게임 폴더 안에 한정했다. 원본 PNG와 캐릭터 디자인은 보존했다. main 병합·수동 배포·결제·패키지 설치·보안 설정 변경 없음.

실물 기기/스크린리더/Safari/Firefox와 실제 청취·사람의 재미 검수는 남았다. 관리 정책의 file:// 차단은 그대로이며 직접 파일 실행 성공으로 주장하지 않는다. 브라우저 내부 route로 독립 HTML을 검사했다.
