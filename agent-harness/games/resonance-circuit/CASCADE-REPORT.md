# 순차 소거 손맛 수정

기준 `c9015b229086a7ce599ef6241ab4107331f3adeb`. 이전120ms 소거+최대24ms stagger는 거의 동시에 지워지는 인상이었다. 이번에는 별도 시각 타임라인으로 순서·팝·빈자리·낙하를 나눴다. 엔진·스킬·패널·캠페인·저장 규칙과 원본 이미지/전투 배경은 변경하지 않았다.

## 순서와 리듬

`timeline.mjs`는 preview가 이미 결정한 소거/덩굴 해제 집합을 한 번 받아 ID별 이벤트를 만든다. 최초 연결은 탭 위치에서 hex BFS로 방문하며 이웃은 실제 화면 각도로 정렬한다. 입력 배열을 뒤집어도 같은 결과다. 방문마다28ms 간격으로 압축 → 밝은 강조 → 작은 팝 → 수축 소거(150ms)가 진행된다.

기존 잔향은 최초 그룹에서 먼저 닿은 표식을 시작점으로 기존 표식에 별도 짧은 전파를 만든다. 폭탄은 자신의 차례에 링을 내고 그 폭탄에서 새로 닿는 실제 소거 타일을38ms 뒤에 배치한다. 이미 지워질 타일은 다시 지우지 않는다. 덩굴은 실제 해제 집합에만 별도 잎 이벤트로 붙고 본체에는 소거 클래스를 붙이지 않는다. 무지개는 자신의 소거 차례에 확정색으로 수렴한다.

큰 연결은 전체 시간을 비례 압축하여 마지막 이벤트 시작을420ms로 제한한다. 마지막 실제 콜백이 실행된 뒤150ms 애니메이션+28ms 빈자리 시간을 보장하고 상태를 한 번만 적용한다. 이후 생존 ID의 이전/새 좌표 차이로120ms 낙하,140ms 후 입력을 돌려준다. 이전 좌표는 문서 좌표로 보관해 스크롤이 가짜 낙하 거리를 만들지 않는다. 새 타일은 짧게 위에서 보충한다.

| 일반 fixture | 마지막 시작 | 해소+낙하 설계 시간 |
|---|---:|---:|
| 1칸 | 0ms | 318ms |
| 6칸 | 140ms | 458ms |
| 10칸 | 252ms | 570ms |
| 42칸 | 420ms | 738ms |
| 폭탄+잔향+덩굴+무지개 | 104ms | 422ms |

이는 정상 실행의 설계 시간이다. 브라우저 메인 스레드가 막히면 실제 시간은 늘어나지만 마지막 타일의 애니메이션을 중간에 끊어 상한에 억지로 맞추지 않는다. 전체 화면 섬광·강한 흔들림을 넣지 않았으며 큰 연결은 마지막 짧은 테두리 강조만 준다.

## 취소·접근성

기본 모션은 모든 소거가 끝날 때까지 기존 보드의 소거 클래스를 유지한다. preview와 상태는 연출 중 다시 계산하지 않으며 상태 적용은 한 번이다. 같은 JS 작업에서 들어오는 중복 입력은 거부한다. 입력 잠금을 `board.dataset.resolving`으로 표시해 검사기도 첫0ms 타이머 이전을 완료로 오인하지 않는다.

새게임을 상태 적용 전에 누르면 연출/예약음을 취소하고 원래 보드로 복원한 뒤 확인창을 연다. 확인창 취소 시 원래 상태가 유지된다. 이미 적용되어 낙하만 남은 짧은 구간에는 요청을 보관했다가 잠금 해제 후 확인창을 연다. 숨김/모션 변경은 연출·예약음을 취소하고 현재 행동을 한 번 정산한다. reduced-motion과 효과 줄이기는 순차 이동 없이 정적 강조/즉시 정산이며 긴 강제 대기가 없다.

스크롤/화면 크기 변경은 화면 좌표 입자·리본을 정리하되 타일 소거 클래스는 건드리지 않는다. 다음 이벤트는 현재 DOM 위치를 읽는다. 숨김/리셋/모션 변경의 전체 정리와 구분했다.

## 순차 음향

고정 음계392–784Hz의 짧은 유리음을 실제 소거 시작에 맞춘다. 모든42칸을 울리지 않고 최소48ms 간격·최대9음을 선택한다. 타일 ID 중복 검사는 유지하면서 일반 강조음의45ms 제한과 분리했다. 시퀀스 중 강조음은6소스까지만 점유해 전체8소스 중 두 자리를 유리음에 남긴다. 기존 기본 무음·마스터 음량·compressor·숨김 정지·캐시 상한은 유지한다.

## 실제 영상·프레임 검수

`cascade-play.mp4`는 실제390×844 브라우저에서 시작·연쇄·잔향·스킬을 조작한 무음 녹화다. 합성 이미지 영상이 아니다. `record_cascade.py`가 CDP 실제 프레임과 타임스탬프를 받아 설치된 ffmpeg로 인코딩했다. 음향은 위 WAV로 따로 확인한다.

`cascade-frame-0.70.png`, `cascade-frame-0.85.png`, `cascade-frame-1.00.png`, `cascade-frame-1.15.png`는 검수용 영상에서 추출해 직접 열어 보았다. 첫 프레임의 보석이 다음 프레임에서 일부만 없어지고 뒤쪽은 팝 상태이며, 이어 빈 경로가 보인 뒤 낙하·보충되는 차이를 확인했다. `cascade-early-{360,390,1280}.png`, `cascade-middle-*.png`도 실제 브라우저 캡처다. 영상의 변화는 확인했으나 이것만으로 사람의 재미를 입증하지 않는다.

## 검사와 발견한 문제

- 기존75개 유지+신규11개 = **86/86**, `timeline-unit-final.log`. 1/6/10/42, BFS 순서/배열 순서 독립, 중복 ID 없음, 실제 폭탄/잔향/덩굴, 타이머 취소, reduced, 늦은 콜백, 스크롤 낙하 보정, 타일 음원 중복/상한 검사.
- 3해상도×모션2종×5fixture **30개 소거 검사 통과 기록**: `timeline-browser-latest.log`. 실제 시작 ID 순서가 계획과 같고, 모든 소거 클래스가 마지막 시작 후 최소120ms 이상 유지되며, 상태가 엔진 단독 실행과 정확히 일치하고, 낙하 후 소거 클래스/ID/입자가 남지 않는다.
- 위 실행 마지막의 모션 취소 검사는 실패했다. 단순 지연으로 추정하고 이벤트를 기다렸으나 재검사에서 실제 설정은 reduce인데 change 알림이 오지 않는 경우를 확인했다. 타일 이벤트/최종 대기에서도 현재 설정을 확인하는 취소 조건을 추가하여 알림만 의존하지 않도록 보강했다. 실패 회귀 `timeline-media-before.log` 후 reset/hidden/motion 취소3경로를 별도 재검사해 모두 종료0(`timeline-cancel-final.log`)을 확인했다. 초기 실패를 감추지 않는다.
- 전체전투: reduced3조합 `timeline-run-0..2.log`, 기본모션3조합 `timeline-run-final-3..5.log`. 이전 일반모션 실행은 검사기의 idle 조건이 첫 예약 이벤트 전의 빈 소거 클래스를 완료로 오인해 실패했다. 명시적인 resolving 상태를 기다리도록 수정했다.
- 배경3해상도×기본/안내9화면: `timeline-background.log`.
- 초기 소거 유지 검사에서 전체 페이지 캡처/resize가 기존 FX clear를 호출해 소거 클래스를 지우는 문제를 발견했다. 화면 좌표 효과만 정리하도록 고쳤다. 별도로 메인 스레드 지연 때 최종 예약 시간이 먼저 도착하는 실패를 재현하고 마지막 실제 콜백 이후 대기를 보장했다(`timeline-stall-before.log`). 스크롤 낙하 보정도 실패 검사 후 추가했다(`timeline-scroll-before.log`).
- reduced의 두 입력을 서로 다른 작업으로 보낸 검사는 첫 행동이 이미 완료되어 정상적인 두 번째 행동이 들어가는 잘못된 기대였다. 동일 JS 작업에서 두 클릭을 보내는 중복 입력 검사로 바로잡았다(`timeline-browser-reduced-initial.log`).
