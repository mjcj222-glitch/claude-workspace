# 릴리스 리뷰 수정 — 안내 미완료 종료 저장 / sprite 하단

## 재현과 원인

기본 시드에서 안내를 끝내지 않고 가장 작은 묶음만 선택하면 18턴에 패배한다. 기존 runTap은 이때 tutorial='chain'을 유지했고, 저장 검증기는 종료 상태에 남은 안내를 거부했다. 자동 저장이 실패하여 새로고침하면 마지막 정상 저장된 생존 상태로 돌아갔다. 안내 미완료 승리에도 동일한 불변식 문제가 있었다.

먼저 승리·패배 재현 테스트를 추가해 두 테스트가 실제 실패함을 확인했다(exit1, tutorial-terminal-before.log). 전투 종료 분기에 skipTutorial(run) 한 줄을 추가해 tutorial='done', tutorialIDs=[]로 정리했다. 저장 검증 규칙을 느슨하게 하거나 기존 전투 규칙을 바꾸지 않았다.

## 검증

- 기존34개와 회귀3개를 합쳐 node:test **37/37 통과**, exit0. 자연 진행18턴 패배, 안내 미완료 승리, 새 잔향을 만드는 타격에서 승리한 경우 모두 직렬화→복원 일치.
- 모듈판/standalone판 각각 패배·승리 **4개 브라우저 경로 통과**, exit0. 패배는 상태 주입 없는 최소 묶음 전략으로18턴에 도달했고, 승리는 종료 직전의 명시적 fixture를 사용했다. 저장 성공 안내와 새로고침 후 동일한 패배/성장 선택 상태, JS 오류 없음을 검사했다. tutorial-terminal-browser.log 및 해당 PNG 참조.
- 360×800/390×844/1280×900 레이아웃, 연쇄·잔향·폭탄·효과 정리 검사 통과. tutorial-fix-layout.log, tutorial-fix-art.log.

## sprite 수정

원본 첫 행 보석의 y=576부터114px 범위는 다음 행 시작 픽셀까지 포함할 수 있었다. 각 타일의 장식 .gem에만 명시적 세로 background-size/position을 적용해 표시 범위를120×108px로 제한했다. 원본 PNG·버튼 크기·인접·입력·캐릭터는 그대로다. manifest도108px로 맞췄다.

새 run-layout-390-False.png를 실제 열어 맨 아래 파랑/노랑 아래의 작은 줄·호가 제거된 것을 확인했다. 보스 작은 상체 크롭은 유지했다.
