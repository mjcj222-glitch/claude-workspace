## 구현 결과

새 게임의 42개 기물은 독립 ID와 실제 x/y 좌표를 갖는다. 고정 1/120초 간격으로 중력, 마찰, 벽·바닥, 원형 기물 간 겹침을 계산한다. 빈 공간이 생기면 생존 기물이 옆으로 밀리고 새 기물은 보드 위에서 들어온다. 기울기도 이동에 따라 바뀐다. 고정 hex 좌표를 흔드는 연출이 아니다.

정착한 실제 좌표로 같은 색 연결, 폭탄 범위, 덩굴 해제, 잔향, 미리보기, 터치를 판정한다. 게임 정산과 최종 좌표는 한 번 계산·저장하고 화면은 계산된 궤적을 재생한다. 재생 중 타일·스킬·과충전을 잠근다. 탭 숨김, 효과 줄이기, 새로고침은 같은 정산 결과를 유지하며 새 접촉으로 자동 소거하지 않는다. 방향키는 실제 위치에서 해당 방향의 기물로 이동한다.

기존 폭탄 전환은 ID·색·잔향·좌표를 보존한다. 새 특수는 탭 색과 새 ID를 사용한다. 새 잔향 후보는 중력 전 최초 그룹의 이웃 중 최종 생존 일반 공격 기물이며 최대 8개다. 새 보드는 x→y→ID, 기존 hex는 열→행 순서다. 폭발만 기존 표식을 건드리면 다른 표식은 발동하지 않고, 새 잔향은 같은 탭에서 발동하지 않는다.

이전 연습 v1 및 탐험 지도 v1/v2 저장은 그대로 읽고 기존 hex 규칙으로 이어간다. 새 게임만 독립 필드 `boardVersion: 1`을 사용한다. 지도 버전과 보드 버전을 혼동하지 않는다. 전투·성장·보상·재도전·모드 전환에서 진행과 RNG를 보존한다.

화면은 전투 무대 → 큰 얼굴 파티 도크 → 시안 체력바 → 퍼즐통 → 과충전 띠 순서다. 기물 사이 여백을 줄이도록 도형을 충돌 원 안에서 키우고, 긴 화면의 상단 빈 공간을 줄였다. 충돌 반지름과 터치 위치를 바꾸지 않아 밀도 수정이 판정을 바꾸지 않는다. 과충전 준비 시 따뜻한 노랑·주황 강조와 “과충전 발동”을 표시한다.

잡몹 요정, 중간보스 황동 사슴, 최종보스 일식 화룡은 새 투명 전신 원화로 전투 무대에 크게 표시한다. 배경 수채화는 흐리게 유지한다. 정예·휴식·상인 장면과 귀여운 동료 얼굴은 유지했다. 6개 방 탐험, 필수 4층 중간보스, 최종보스, 유물, 3전투 연습, 튜토리얼, 승패·재시작·저장 분리는 모두 실제 진행 검사를 거쳤다.

## 수정 과정에서 확인한 실패

초기 물리 배치에서 일부 시드가 상단 경계를 넘거나 입구에 남았고 작은 겹침이 생겼다. 반지름 범위, 입구 진입, 충돌 여유와 최종 투영을 수정한 뒤 100개 시드 검사와 실제 탭·완주를 통과했다. 초기 통합에서는 `adjacent` 이름 가림으로 오류가 났고 지역 변수 이름을 고쳤다.

첫 탐험 검사에서 다른 모드 저장의 JSON 필드 순서가 바뀌는 문제가 드러났다. 저장 해독기가 허용된 타일 필드 순서를 보존하도록 고치고 직렬화 동등성 검사를 추가했다. 그 뒤 6개 탐험 조합이 통과했다. 과충전 화면 검사 첫 fixture는 저장 wrapper가 없어 거부되었으며 올바른 v1 wrapper로 다시 검수했다. 초기 오류 로그는 `flow-*-initial.log`, `flow-integration-first.log`, `flow-red.log`, `flow-ready.log` 등에 남겼다.

전신 원화 첫 생성은 사슴 뿔이 옆 셀을 침범했다. 두 번째 생성에서 셀 여백을 확보하고 실제 픽셀과 브라우저 가시 영역을 확인했다. 채택한 원본은 `assets/enemy-foreground-sheet.png`이며 생성 이미지의 픽셀을 후처리하지 않았다.

## 출처와 접근 제한

전신 원화는 사용자가 승인한 내장 이미지 생성 도구로 독자적인 펜선·수채화 캐릭터를 생성했다. 기존 귀여운 동료 얼굴과 온실 그림의 화풍을 참고했으며 원작 게임의 자산·로고·음악·캐릭터를 복제하지 않았다. 출처·해시·크기·셀 범위는 `assets/manifest.json`에 있다. 게임에는 외부 이미지 호출이나 유료 API가 없다.

제공된 참고 이미지 2개는 Library 전달 단계에서 `download failed`로 종료 1이었다. 승인된 기본 경로 재시도도 반환 파일이 이 실행 환경에 없어 종료 1이었다. 실제 참고 픽셀은 이 환경에서 보지 못했고 추가 재시도는 중단했다. 총괄 및 별도 검토자가 확인한 설명을 바탕으로 구현했다. 이 제한은 참고 파일 접근 실패이며 GitHub 게시 제한은 아니다.

개발 환경의 `file://` 직접 열기는 관리 정책으로 차단되어 직접 실행을 재시도하거나 정책을 바꾸지 않았다. 동일 단일 HTML의 실제 플레이는 서버를 띄우지 않고 Playwright의 브라우저 응답 경로로 검수했다. 사용자의 실제 로컬 파일 실행은 별도로 확인해야 한다.

## 파일·실행·남은 한계

`resonance-circuit.zip`을 풀고 `standalone.html`을 연다. 모듈판은 이 폴더에서 `python -m http.server 8000 --bind 127.0.0.1`을 실행한 뒤 로컬 브라우저로 접속한다. 패키지 재생성은 `python package_game.py`다. `flow-package.log`에서 ZIP CRC, 각 파일 일치, 내장 자산 해시, 크기를 확인할 수 있다.

롤백은 승인 후 PR의 해당 커밋을 되돌리는 방식으로 제안한다. 현재 자동 병합이나 롤백을 실행하지 않았다. Issue #1의 예약 연구·사용자 PC 전원 OFF 검증은 이번 게임 개발 작업으로 완료했다고 표시하지 않는다.
