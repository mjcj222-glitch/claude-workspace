기준은 PR #3의 `74a92ac`이며 한 전투 범위만 보완했다. 웹판과 main은 변경하지 않았다.

영상은720×1280,1301프레임,21.683초, H.264 MP4,5,666,568바이트다.
Godot Movie Maker에서 고정60fps로 직접 렌더했으며 기록에는 약66.1초가 걸렸다.
입력 이벤트로 스킬, 큰폭탄 획득·사용, 회복, 주인공 공격과 리필을 실행했다.
headless 로그로 화면을 합성한 영상이 아니며 **실시간60fps 성능 측정도 아니다**.

## 반영한 시각 요구

- 1254×1254 RGBA 주인공 원본 세 장의 얼굴·그림체·픽셀을 보존했다.
  왼발 접점을 맞추고 몸 높이를234 logical px로 정규화했다.
  준비0.14초 → 베기0.10초 → 복귀0.18초 후 대기로 돌아온다.
  복귀는 대기 원본으로 전환하는 것으로, 별도의 복귀 원화를 만든 것은 아니다.
- 실제 배경 합성에서 원본 알파를 검수하고 유지했다. 낮은 알파 색 잔여를
  원본 파일에서 제거했다고 주장하지 않는다.
- 고채도 기물의 어두운 측면·밝은 베벨·상단 음영·사선 광택을 같은 외곽 안에 그린다.
  보드와 주변은 검정~중성 회색이다. 배경 이미지의 최초 자연 크기가 지정 영역을
  넘던 문제도 수정하여 스토리 배경은720×390 영역 안에만 표시한다.
- 큰폭탄은 큰 폭탄 심벌과 BOMB, 이중 금색 테두리·약한 맥동으로 구분한다.
  소형 폭탄은 작은 심벌·단일 테두리, 차지는 번개, 잔향은 ECHO·청백색 이중 호로 구분한다.
- 선택 윤곽·연결선·선택 수·제거 예고 수·피해/회복 정보를 표시한다.
  소거는0.065초 압축 →0.065초 팽창 →0.070초 파열이다.
  그리기 변환은 입력이 잠긴 정산 중에만 적용하며 물리 위치와 충돌체는 바꾸지 않는다.
- Kenney CC0 텍스처 여섯 개로 예고·소거·큰폭탄·피격·스킬의 강도를 구분한다.
  전체 화면 플래시와 화면 흔들림은 사용하지 않는다. 움직임 줄이기를 지원한다.
  [출처와 라이선스](assets/SOURCES.md), [원본 해시](assets/integration-sources.json)를 보존했다.

| 저장소 harness |check 통과, unittest5/5|

실제 OS 입력으로 스킬 버튼, 기물 예고/확정, 예고 ID와 실제 사라진 ID 일치,
42개 리필·바닥 지지·탈출 없음, 재시작을 확인했다. 두 자동 전투 정책 모두
시간 초과·교착 없이 종료했다. 외형·충돌체·터치 폴리곤은 같고 연결 그래프는
같은 외곽의 거리1.0 기준이다. 픽셀 접촉 오차0이나 기기 간 결정론을 주장하지 않는다.

축소 창에서 정산이 없던 원인은 검사 코드가 논리 좌표를 창 좌표로 바로
전달한 것이었다. `Viewport.get_final_transform()`으로 배율과 letterbox
오프셋을 적용했다. 실제 게임 입력을 이중 변환하거나 물리 부모 scale을 바꾸지 않았다.
OS 검사의 초점과 ACK 파일 경쟁도 검사 driver에서 수정했다.
소거 후 연결선만 남는 현상은 실패하는 회귀 검사로 재현한 뒤 파열 시 지우도록 고쳤다.

전체 결과는 [검증 체크포인트](VALIDATION.md)와 `evidence/local-integration/`의
최종 로그·화면·메타데이터·해시에 보존했다.
