# 출발 선택과 두 가지 퍼즐 운영

기준 소스0b4e0a7 위에 기존3전투·경로·상점·보스·유물·타격 피드백을 보존하고, **한 판 시작 때 한 명만 고르는 출발 화면**을 연결했다. 파티 모집이나 영구 성장, 새 전투를 추가하지 않았다. 아래 능력은 작은 플레이 검증을 위한 설계이며 재미·최종 밸런스가 확정된 것은 아니다.

| 캐릭터 | 실제 스킬 | 플레이 차이 | 번짐 안료 |
|---|---|---|---|
| 리오 · 변환사 | 색을 고른 뒤 가까운 일반 공격 패널 최대4개 변환 | 큰 직접 연결·핵 생성·약점색을 준비 | 변환4→5개, 기존 그대로 |
| 노아 · 핵술사 | 일반 공격 패널1개를 같은 색 물감핵으로 변경 | 폭발 시작점을 심고 다음 수동 소거 시점을 선택 | 이번 시전에 심는 핵만 일반→강화, 접촉1→2단계 |

노아 설치는 **원래 ID·위치·색·반경을 유지한 kind 변경**이다. 새 ID·보충·즉시 피해·회복·소거 행동·충전·경감은 발생하지 않는다. 하트와 기존 핵은 설치할 수 없다. 심은 핵은 이후 기존 core/strong 규칙을 그대로 쓰며, 핵 객체 자체는 직접 일반 개수·일반 피해·약점 W에 포함되지 않는다. 일반 패널 하나를 핵으로 바꾸는 비용과 나중에 기동할 선택이 존재한다. 두 캐릭터 모두 사용 후 유효 수동 소거3회로 충전하고, 잿빛 보석 예약을 실제 사용으로 소비한 주기만2회다.

응축 렌즈5/11와 잿빛 보석의 **직접 일반6개** 조건은 양쪽에 그대로 적용한다. 기존 핵 소급 강화, 스킬 중 적 예고 재계산, 미래 보충색을 이용한 보스 기회 제조는 없다. 획득 유물은 다음 계획부터 적용한다. 노아의 reward/detail/shop 문구는 실제 강화핵 효과를 표시한다. 리오는 기존 canonical skill planner에 위임한다.

## 시작·학습·복귀

- 카드를 누르고 놓으면 후보만 선택한다. 별도의 출발 버튼에서 확정한 한 명을3전투 동안 유지한다. 출발 후 API와 UI로 재선택할 수 없다.
- 첫 전투의 짧은 안내가 캐릭터별 스킬 준비→대상 선택→후속 소거를 알려준다. 설치 직후에는 핵을 단독으로 눌러도 행동1회임을 안내한다. 무효 대상 안내도 하트/핵과 일반 소거를 구분한다. 강제 유리 보드나 별도 보상은 없다.
- 하단 스킬 이름, 준비/충전, 실제2/3 요구량, 성공한 시전의 컷인 이름이 선택한 캐릭터를 따른다. 노아에게 색 선택 메뉴는 노출하지 않는다. 두 캐릭터의 초상은 기존 원본을 공유하며 노아에 **임시 초상**을 표시했다. 실패한 이미지 전송은 재시도하지 않았다.
- 승리·패배 화면에 선택한 캐릭터가 나타나며, 버튼은 새 출발 선택으로 돌아간다. 리셋도 보드·HP·금액·유물·예약·충전·선택·시전 횟수·입력 후보·FX·음향을 초기화한다. 음소거/효과 절제 선호는 유지한다.
- 카드와 출발은 새 down/up 및 serial을 요구한다. 이탈·포커스 상실·다른 손가락·중복 놓기로 확정/소거가 새로 발생하지 않는다. 보이는 소리 제어는 출발/보상 상태에서도 포인터 경합 없이 작동한다.

## 실제 검증과 증거

- 기존38개 회귀와 새 캐릭터/입력/상호작용3개 스크립트를 `tests/run_character_regressions.py`로 실행한다. 최종 명령·결과는 [final-regression/results.json](../evidence/characters/final-regression/results.json)에 남긴다. 기존 실제 장면 검사는 `enter_adventure.gd`의 정상 카드/출발 제스처를 명시하며, sandbox/standalone 세션 API는 보존한다. 리셋의 의도된 새 목적지만 ready→departure로 수정했다.
- 능력/동결 계획/유물/약점/보스 경계, 하트·기존 핵 제외, 최대 충전, 중복, 취소, 전투 중 변경 금지, 결과/리셋을 검증했다. 기존 접촉/중간 경로/반복 보충/저장된 stall 재현/타격 동기화 회귀를 유지한다.
- 360×640·390×844 창의 실제 OS 마우스 검사 각각40개 통과. 후보/출발, 이탈 취소, 패널 역변환, 설치,2/3충전, 유물 설명의 입력 차단, 리오 색 선택, 결과 복귀를 포함한다. **충전2·보유 유물 설명·결과의 작은 창 사진은 명시적 상태 fixture**이며 보상을 실제 얻은 증거로 계산하지 않는다. [windows](../evidence/characters/windows)
- 정상 초기 보드 seed20261021에서 각 캐릭터가 안전/정예×세 유물 쌍,6개씩 총12개 fixed-step 정상 시뮬레이션을 승리했다. 리오12~17회·HP20~28, 노아15~19회·HP24~26. 노아 강화핵 설치는 각 경로에서 실제2~4회 관찰됐다. 강제 보드/HP/골드/충전·중간 리셋은 없다. 각 캐릭터의 별도 attrition 정책도20회에 HP0으로 패배 완료했다. 이 정책은 회복을 선호하지 않고 낮은 즉시 피해를 고르며 첫 스킬만 쓰는 진단용 자동 조작이지 사람의 실력 모델이 아니다. [리오 요약](../evidence/characters/normal-summary-rio.json), [노아 요약](../evidence/characters/normal-summary-noa.json)
- **실제 main 장면의 정상 조작·자연 process/refill**에서도 리오 안전 경로13회·HP20 승리, 노아 정예 경로15회·HP24 승리, 양쪽 attrition20회·HP0 패배를 각각 기록했다. 네 실행 모두 오류 없이 결과에서 출발 선택으로 돌아왔다. 자동으로 합법 입력을 선택한 native 실행이며 사람 플레이/실물 터치 검증은 아니다. 사진 저장/결정 계산/일부 동시 실행이 포함되므로 이 흐름의 벽시계를 성능 수치로 쓰지 않는다.
- [독립 소스·실제 화면 검토](../evidence/characters/independent-review.md). 현재 확인된 차단 결함은 없지만 소수의 자동 정책 통과가 캐릭터 균형·전략의 깊이·재미를 입증하지 않는다.

## 별도 native 성능 비교

[측정 원본·요약](../evidence/characters/native-performance.json):0b4e0a7와 현재 소스를 동일한 llvmpipe 환경에서 순차1회씩, 사전 기록한 같은16회 소거 입력으로 재생했다. 출발 UI는 측정 시작 전이며, 측정 중 정책 탐색·스크린샷·파일 저장·다른 Godot/인코딩 작업은 제외했다. 공통 wrapper와 메모리 로그의 비용은 양쪽에 포함된다. **canonical 결과 행·물리 tick/반복·공급/정착 시간 기록·최종 상태가 일치**했다. 리오 보존 입력의 비교이며 두 캐릭터 자체의 난이도 비교가 아니다.

| 관측값 | 이전 | 이후 |
|---|---:|---:|
| 보드 누름→첫 draw 중앙값 |18.971ms|19.906ms|
| 일반 소거→준비 중앙값(15회) |823.162ms|852.618ms|
| 일반 소거→준비 범위 |654.694~1483.398ms|653.611~1484.259ms|
| 코어 소거1회 |1125.425ms|1120.084ms|

일반 소거 중앙값은 이 한 쌍에서 약29ms 증가했다. 통계적으로 안정된 성능 동등/악화 원인/속도 개선은 주장하지 않는다. 일부 표본은0.6~1.0초 목표 밖이다. 물리·준비 판정·timeout을 바꿔 이를 숨기지 않았다. 프레임에 맞춘 programmatic 입력과 cloud software GL은 OS/모바일 입력 지연이 아니다.

## 실패 기록과 남은 범위

처음에는 새 API가 없어 캐릭터/진입 테스트가 RED였다. 구현 중의 GDScript 변수/native-class 이름 충돌과 창 테스트의 혼합 들여쓰기 오류는 고친 뒤 재검증했고 로그를 보존했다. 첫 전체 회귀 호출은 writable XDG 설정을 빠뜨려 홈 데이터 디렉터리 생성 오류로 실행되지 않았다. 설정을 원래 승인된 `/tmp/chroma-tools`로 맞춘 후 검사했으며, 홈 권한이나 보안을 변경하지 않았다. 출발 화면의 보이는 소리 제어가 동작하지 않는 RED도 실제로 확인하고 입력 경합을 유지하는 작은 수정으로 GREEN을 확인했다.

기존 seed23의 정확한 저장 보충 상태는 수정 회귀가 통과한다. 이전의 긴 입력 시퀀스는 앞선 접촉 수정 뒤 ID가 달라지는 한계가 남으며, 이를 원본 시퀀스의 완전 동일 재생 성공으로 바꾸어 보고하지 않는다. 이번 작업은 물리 소스를 바꾸지 않았다.

현재 Windows/Web 최신 묶음·실기기·중단 저장/복귀는 제공/검증하지 않았다. 오래된 ZIP을 최신으로 표시하지 않는다. 이후에는 두 능력의 실제 사람 플레이·학습 이해도와 유물 후보/적 전조의 다양성을 작게 검증할 필요가 있다. 장기 지도·영구 성장·가챠·유료 기능은 이번 작업에 없다.
