## 구현

이전0b363ff의 작은 코드 도형 캐릭터와 정적 콤보 상자를 교체했다. 공식 이미지 생성 도구로 만든 원본 치비 시트에서 얼굴·상반신을 표시한다. 원본 PNG는 변경하지 않았으며 nearest 필터와 정수 위치, 대기/준비/스킬/환호/피격의 상반신 변형과 장식을 사용한다. 수작업 저해상도 픽셀 프레임이나 표정별 애니메이션은 아니다. `assets/characters/README.md` 참고.

실제 제거마다 동적 숫자와 팝/차임이 발생하고 빛은 적 대신 축적점에 모인다. 처음 두 소거는 실제 적 HP/보호막을 바꾸지 않는다. 세 번째 소거와 낙하 뒤0.28초 방출 준비, 한 번의 피해 적용,0.24초 적중 표시 후 보상/반격으로 진행한다. 치명타에도 같은 순서를 유지한다. 순차 소거 간격은0.075초를 기준으로 전체2.1초 이내로 압축한다. 기존0.28초 일괄 압축보다 긴 의도적 리듬이며 전체 입력 잠금 시간이 전혀 늘지 않았다고 주장하지 않는다. 준비/적중 이외의 빈 대기 시간은 넣지 않았다.

보호막 예약 감소로 다음 미리보기의 유효 내구를 계산하되 실제 감소와 파편은 최종 적중에서 발생한다. 하트 회복·기술 충전·고정 낙하·조건부 수호 꽃잎·폭탄37/48 물리 및98/164 폭풍은 유지한다. 기본피해와 약점 계산식은 유지하지만 치명타 조기종료가3회 후로 바뀌므로 이전 실행과 전투별 소거 횟수는 달라질 수 있다.

저장v3은 축적량과 정산 상태를 저장한다. v1/v2는 기존에 적용한 피해를 다시 더하지 않고 빈 축적량으로 읽는다. 중간 턴의 남은 소거만 새 방식으로 축적한다. 읽기만으로 원본을 변경하지 않는다. 세 번째 연출 중 중단은 첫2회까지의 안정 체크포인트로 돌아가며 중간 프레임 저장은 지원하지 않는다.

## 시각·음향 검토

`hero-art`는 실제360px 화면과 원화 후보다. `banked-impact/presentation-fixture.mp4`는 합성 연출 시험이며 정상 플레이로 표시하지 않는다. 실제 게임 비교 영상은 별도로 캡처한다. 최초 정상 영상에서 치명타 순간 보상창이 피니시를 가려0.24초 적중 상태를 추가했다. 밝은 보스 배경에 묻히는 축적점에는 원형 어두운 배경과 글자 외곽선을 추가했다. 원본 게임의 영상을 실제 재생/청취하지 못했으며 공식 FAQ의3탭/선택적 카운트 스킵과 사용자의 리듬 지시를 구분한다.

합성 믹스 피크 -9.752dBFS, 클리핑/비정상 샘플0은 해당 시험의 수치다. 실제 비교 영상23.621초/480×766/60fps, AAC48kHz 스테레오, 피크 -9.556dBFS, RMS -31.496dBFS, 클리핑/비정상 샘플0. 매체 검증 파일에 별도 기록한다. Linux Dummy 오디오/파일 분석은 실제 스피커·헤드폰 청취가 아니며 Windows 실행을 대신하지 않는다. 영상 종료용 시험 스크립트의 미완료 coroutine 때문에 나온 자원 경고는 `opening-teardown-before.log`에 보존하고, 기존 드라이버가 정상 종료하게 수정했다.

## 전달과 한계

Windows 후보는 이전 Library 파일을 바꾸지 않고 별도 이름/커밋 manifest로 만든다. 알려진 공식 Windows 템플릿을 재사용하며 새 다운로드/설치/유료 서비스는 없다. ZIP CRC·새 압축 해제·원격 커밋과 소스 해시·PCK 자원·개인 메타데이터 제외를 확인한다. 동일 PCK의 Linux 로드/축적2회 이어하기 해시를 검증하지만 Windows 실제 실행은 미검증이다.

GitHub CI는 하네스 검사이며 이 Godot 실행 결과와 별개다. 기존 Vercel 자동 프리뷰 상태도 Godot Web 실행 검증을 뜻하지 않는다. PR3 draft/unmerged 유지. 새 고유능력은 `ABILITY_FOLLOWUP.md`의 후속 설계이며 이번 아트·리듬 후보에는 구현하지 않았다.

중복 통과한 중간 실행 로그는 클라우드 작업 디렉터리에 보존하고 최종 실행 및 최초 실패 로그를 공개 증거로 선택했다.
