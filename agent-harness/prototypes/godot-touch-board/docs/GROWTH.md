## 규칙과 입력

- **번짐 안료:** 시작 패널 포함 스킬 최대4→5개. 일반 패널만 접촉 그래프의 거리/ID 순으로 대상과 경로에 사용합니다.
- **응축 렌즈:** 직접 연결 일반 패널의 생성 기준6/12→5/11개. 한 번에 핵 하나만 생성하고11개 이상은 강화핵만 만듭니다. 하트·기존 핵·추가 연쇄는 세지 않습니다.
- **잿빛 보석:** 직접 일반6개 이상에서 다음 스킬 사용 후의 충전3→2회를 하나 예약합니다. 현재 충전에는 소급하지 않습니다. 다음 유효 스킬에만 소비하고 그다음 예약 없는 사용은 다시3회입니다. 렌즈의5개 기준과 별개입니다.

누르는 순간 보드/보유 유물과 예약 상태로 계획을 만들고 해제에서 같은 계획을 실행합니다. 수동 행동·현재 충전·통계는 한 번만 집계합니다. 기존 소거와 핵 연쇄, 새 핵 생성 뒤 자연 보충을 마친 시점에 보상을 엽니다. 보상 획득은 다음 입력부터 적용하며 직전 결과를 다시 계산하지 않습니다.

보상은 제안 식별자와 포인터, 새 누름/같은 카드 해제를 확인해 한 번 확정합니다. 보드/스킬을 잠그고 리셋을 허용합니다. 영역 이탈·초점 상실·시스템 취소는 선택 후보만 버리고 제안은 남깁니다. 리셋은 보드·유물·보상 회차·예약·충전 요구·통계를 모두 초기화하고 스킬을 준비시킵니다. 구간 통계는 첫9회에 고정됩니다.

## 정상 플레이에서 발견한 상단 걸림 수정

최대 연결을 택하던 초기 자동 플레이의7번째 소거에서 공급은 끝났지만 id94의 몸체 상단이285.10px로 보드 상단290px보다 약4.9px 높게 남았습니다. 속도나 단순 종료 시점이 아니라 **유입 위치 선택** 문제였습니다. [실패 화면](../evidence/growth/stall-pair0.png), [종료 상태](../evidence/growth/stall-pair0.json), [원래 소거/유물 순서](../evidence/growth/greedy-stall-pair0.json), [동일 보충 시작 스냅샷](../evidence/growth/stall-start-pair0.dat)을 보존했습니다.

[생성 순간 기록](../evidence/growth/inlet-red.json)에서 id94는0.200초에 가장 낮은 현재 입구를 골랐지만 첫 접촉 중심높이가316.08px여서 전체 몸체를 수용할 최소327px보다 높았습니다. 다른 낙하체가 낮은 입구를 일시 점유할 때, 기존 공급 로직은 시작점만 비어 있으면 높은 더미에도 넣었습니다. 종료 제한을 늘려 해결할 문제가 아닙니다.

`_spawn()`에 현재 첫 접촉 높이가 `보드 상단+반지름` 이상인지 확인하는 조건 하나를 추가했습니다. 적합한 입구가 없으면 pending에 유지하고 다음 tick에서 현재 표면을 다시 봅니다. 생존자 위치/ID, 중력·속도·충돌 반복, 정착 판정과4초 제한은 그대로입니다. 강제 이동이나 목표 좌표 재배치는 없습니다.

**정확히 저장된7번째 보충 시작 상태**는 기존 조건에서4.008초 중단을 재현했고, 수정 후0.816667시뮬레이션 초에48개 전체 몸체가 들어왔습니다. [수정 후 모든 중간 프레임과 공급 기록](../evidence/growth/inlet-green.json): 최대 겹침0.0257px, swept 겹침0.0593px, 한 tick 이동9.2876px, 충돌 없이 횡이동0건. id94는0.242초의 다른 입구가 수용 가능할 때 들어옵니다. 이 시간은 순수 시뮬레이션 값이며 실제 렌더 벽시계와 다릅니다. [최대 연결 정책의 전체9회 재실행](../evidence/growth/play-pair0-greedy.json)도 통과했습니다. 입구 공급이 달라지므로 이후 자동 플레이가 고르는 패널은 달라질 수 있으며, 동일 상태 회귀는 별도 저장 스냅샷으로 확인했습니다.

원래 입력 보존을 위해 테스트에서 이전 공급 조건 하나만 메모리 내에 복원해 [원래 시드·화면 좌표·선택 ID·보상 순서](../evidence/growth/play-pair0-before-inlet.json)를 다시 기록했고 같은7회 중단을 확인했습니다. `play_growth.gd -- --pair=0 --greedy-stress --before-inlet`은 의도한 red 재현입니다. 수정본에 [화면 좌표 그대로](../evidence/growth/input-replay.json), [같은 ID를 현재 위치에서 선택](../evidence/growth/input-replay-ids.json)도 시도했으나, 공급이 이미 앞선 행동의 접촉을 바꾸므로4번째 소거에서 원래 대상이 고립되어 무효가 됩니다. 두 전체 입력 재생은 **미통과 진단**으로 남겼으며 정상 진행 통과로 계산하지 않았습니다. 동일한7번째 실패 상태의 복구는 위 `.dat`에 보존된 정확한 위치·ID·색·대기 패널을 사용하는 `test_refill_inlet.gd`로 분리해 검증했습니다.
