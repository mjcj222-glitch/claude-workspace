# 저장 실패 및 종료 안정화 설계 — 2026-10-22

기준: 3397e37. gameplay/physics/seed/음향 파형 변경 없음. 기존 후보 보존.

## 확인한 원인과 재현

`board_lifecycle.checkpoint`는 save/close_run 실패 후에도 dirty=false를 설정한다. 이후 입력 release가 없으면 저장/완료 장벽을 재시도하지 않는다. 실제 임시 파일 경로에 디렉터리 장애물을 두어 open 실패와 입력 없는 복구 실패를 재현한다. OS 창 닫기는 자동 종료라 완료 장벽 실패를 확인하지 않고 이전 저장을 남긴다. 저장 자체가 불가능한 환경에서 강제 종료까지 막는 내구성 보장은 불가능하다.

오디오는 별도로 12회 생성/play/reset/free 후 verbose 종료를 조사한다. 단순 대기 추가나 로그 억제는 수정으로 간주하지 않는다. 최소 AudioStreamPlayer 재현 및 런타임 비교 후 소유권 문제가 확인되면 해당 경로만 수정한다.

## 제한된 변경 계획

1. 실패한 저장 요청과 마지막 안정 상태를 유지한다. 최초 시도 후 1/3/7초 간격으로 최대 3회 자동 재시도. 입력 연타나 새 상태가 실패 예산을 재시작하지 않는다. stable boundary에서 최신 상태로 갱신하며 held/busy 중 현재 상태는 저장하지 않는다.
2. 안내에 미저장 상태와 자동 재시도/중단을 표시한다. 안내를 눌러 명시적으로 다시 시도할 수 있다. 게임 입력은 계속 가능하고 성공 시에만 오류를 지운다.
3. 창 닫기에서는 마지막 안정 상태 또는 terminal 장벽을 한 번 시도한다. 실패하면 재시도 후 종료/저장 없이 종료 선택을 제공한다. 영구 장애 시 종료를 무한 차단하지 않으며 강제 종료·전원 장애에서는 이전 저장이 남을 수 있음을 명시한다.
4. 현재 파일 읽기 자체 실패를 손상 데이터로 취급해 덮어쓰지 않는다. 원본·유효 backup·미완료 쓰기의 복구 의미를 유지한다.

## 테스트 불변식

실제 open/rename 장애, 제어된 짧은 쓰기/용량 부족/읽기 전용 오류 주입은 격리된 tmpdir에서만 수행한다. 실패 시 current와 valid backup 보존, 재시도 횟수/간격 상한, 추가 입력 없는 복구, 재시도 중 held/busy 스냅샷 금지, 보상/상점 중복 없음, 완료 후 재개 차단, 실패 종료 경고/명시 종료, 새 탐험 보관 실패 보존을 검증한다. 강제 종료된 tmp는 current로 승격하지 않는다.

기존 52개 회귀, 저장/컨트롤러 검사, 두 전체 continuous/resumed 비교와 interruption, 기존 창/수명주기 및 정상 win/loss를 재실행한다. 오디오 반복 scene/reset/quit 진단을 그대로 기록하고 남는 엔진 경고는 범위를 명시한다. 검증 후 PR3만 커밋/푸시, 정확한 HEAD/하네스 CI 확인. 새 Windows 후보는 별도 이름이며 Windows 실제 실행과 Linux PCK 검사는 구분한다.
