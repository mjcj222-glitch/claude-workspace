# 축적 후 한 방 · 아트 교정 계획 (2026-10-22)

최신 사용자 교정은 이전 '블럭마다 적에게 궤적' 방향을 대체한다. 공식 FAQ https://crashfever.com/faq/faq_cat/faq6/ (2026-10-22 직접 확인)는 기본3탭 뒤 공격과 선택적 카운트 스킵을 설명한다. 원작 동영상을 실제 재생/청취한 것은 아니다. 정확한 소리 리듬은 사용자 요청의 '띵띵 축적 후 빠앙'을 우리 게임의 설계 기준으로 삼는다. 개인 참고 이미지는 저장소 밖에서만 읽었다.

## 통합 계약
- 유효 소거1회는 여전히 행동1회. 처음2회에는 피해/보호막 감소를 pending ledger에 축적한다. 실제 enemyHP/shieldHP는 변하지 않는다.3번째 소거와 낙하 뒤 player_attack 단계에서 축적량을 정확히 한 번 적용한다. 그 뒤 승리/보상 또는 반격. 처음 소거가 치명적이어도3회까지 축적하며 UI에 명확히 표시.
- 하트 회복, 기술 충전, 고정 낙하 카운트는 각소거 계약을 유지한다. 기술은 여전히 무행동/무피해다. 수호 꽃잎은 조건부 예고 약화만 유지한다.
- 각 소거의 보호막 계산은 실제내구에서 앞서 축적한 감소를 뺀 유효내구로 계획한다. 파괴 보너스는 해당소거에 한 번만 축적; 실제 내구/HP/파편은 최종 공격에서 적용. 미리보기는 '축적 +N'과 보호막 예정 감소로 구분한다.
- pending damage/shield/removed/base/weak/counts와 attack-settled flag를 저장3에 기록. 저장1/2는 이미 적용된 피해를 다시 축적하지 않고 pending0으로 읽는다. 이전actions_in_turn1/2는 유지하여 남은소거만 모은 뒤 한 번 공격한다. 원본 읽기 보존/백업/종료 barrier 유지.
- 숫자는 실제 제거 이벤트에서만 증가하고 탄성/기울기/잔상/색 변화. 고정 큰 판넬 제거. 제거 중 적탄환/적중숫자 없음, 에너지는 별도 축적점으로 이동.3회 뒤 한 번의 피니시가 크기에 비례. 효과 감소는 읽기 유지/과도한움직임 생략.
- 제거 간격은 현재 최대0.28초 압축을 해제하고 약0.075초, 전체 순차 구간은2.1초 상한. 별도 무반응 지연은 추가하지 않음. 실제오디오로 리듬을 보여주고 사람청취 검증과 구분.
- 공식 이미지 생성으로 만든 원본 상세치비 후보를 atlas로 사용, 하단 얼굴이 읽히는 bust/nearest 및 정수좌표, 대기/준비/스킬/환호. 엄격한 수작업픽셀 스프라이트라고 주장하지 않음. 고품질 성공을 테스트만으로 단정하지 않음.

1. 첫2회 실제HP불변/3회원샷/치명타-보상-반격 순서,하트/보호막/수호꽃잎/고정낙하/중복release.
2. 중간pending저장/재개와마지막공격중단 복구, 이전버전 저장 실제읽기, 손상/쓰기실패 기존회귀.
3. 이전전체회귀의 의도적계약변경과진짜결함 구분, 정상두캐릭터승패,작은창.
4. 아트확대및하단후보 공개검토, 저/고연쇄 실제소리영상, 클리핑/정확한카운트/단일impact.
5. PR3 한정검증커밋과CI, 별도Windows후보/Library. 이전후보보존. 신규유물은 조사결과 전 추가하지 않음.

실제 촬영 보정: 치명타 적중과 동시에 보상창이 열려 피니시를 가렸다. HP 적용은 적중 순간 유지하되 player_impact 0.24초 후 보상/반격으로 진행한다. 이 구간은 입력/저장 안정 상태가 아니며 직전 안정 체크포인트로 복구한다.
