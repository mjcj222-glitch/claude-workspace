## 원본 자산과 작은 화면
두1254×1254 RGBA 원본을 현재 Library 지원 경로로 이 환경에 정상 materialize하고 직접 확인한 뒤 공개 승인된 자산 폴더에 추가했습니다. 사용자 참조 이미지는 포함하지 않았습니다.

- 연금술사: 원본 상반신에서 얼굴 중심 영역을130×112 논리 픽셀 초상으로 표시. 테두리 있는 초상 구도이며 전체 상반신을 보여주는 것으로 오인시키지 않습니다. 스킬 시 초상 테두리만 강조합니다.
- 훈련 젤리 골렘: 투명 여백을 제외한 영역을 약193×166 논리 픽셀로 표시. 원본 종횡비를 보존하고 피해 시 작은 흔들림·색·반짝임만 추가합니다.
- [원본 크기/표시 영역 기록](../assets/ART.md). PNG 원본은 재도색/리사이즈하지 않았고 Godot texture region 및 mipmap으로 표시합니다.

360px 창에서는 캐릭터65×56, 표적 약96×83, 색 버튼60×44px입니다. 주요 설명/충전/결과는22논리 px 이상(360폭에서11px), 색 이름24논리 px입니다. 실제 캡처를 확인하여 주요 영역에 글자/숫자 겹침이 없음을 확인했습니다. 작은 보조 글씨의 가독성과 얼굴 세부는 실물 기기·사용자 판단이 남습니다.

초기 `canvas_items` 작은 창 검사에서는 내부 texture가180×270으로 보고되어 글자가 거칠었습니다. 크기/배율을 계측한 뒤 `viewport` 모드의720×1080 기준 렌더로 바꿨고, 두 창에서 동일 기반 해상도를 확인했습니다. 이 환경의 관찰이며 모든 Godot 환경의 결함이라고 일반화하지 않습니다. 축소 PNG에는 mipmap+linear filtering을 사용합니다. 설정 의미는 [Godot 공식 다중 해상도 문서](https://docs.godotengine.org/en/stable/tutorials/rendering/multiple_resolutions.html)를 참고했습니다.

실제 인증된 XTest 마우스로 두 창에서 스킬 열기→네 번째 색 선택→표시된 패널 변환→리셋을 실행해 모두 통과했습니다. 숨겨진 팔레트 무효, 전체 보드 표시 범위, 스킬이 소거 행동을 쓰지 않는 것도 검사했습니다. `tests/small_window_driver.py WIDTH HEIGHT`는 기존 DISPLAY/XAUTHORITY 환경에서 이 검사를 재현합니다. Android 손가락·Windows·브라우저 실행 검사는 아닙니다.

## 긴 연쇄 대기
큰 연쇄의 기존 길이는 소거 연출 약0.637초 + 낙하 벽시계2.078초였습니다. 낙하 중 CPU 충돌0.702초는 그 벽시계에 포함되고, 실제 시뮬레이션1.767초/마지막 공급1.408초/마지막 안정 확인0.058초는 서로 겹치는 시간입니다. 이들을 더해 전체 대기로 계산하지 않았습니다.

13개 이상 소거에만 각 패널의 순차 onset 전체 길이를 최대0.28초로 제한하고 마지막 패널0.10초 fade가 끝난 뒤 보충합니다. 순서·소리 이벤트·모든 패널 처리·최종 미리보기 결과는 유지합니다.12개 이하는 기존 타이밍을 유지합니다. 테스트가 기존35/48개 연출에서 실패함을 확인한 뒤 수정했습니다.
