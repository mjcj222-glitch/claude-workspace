# 색 폭탄과 동색 연결

기준 4a500ec. 사용자가 승인한 자체 구현이며 원작의 정확한 복제라고 주장하지 않는다. 캐릭터·유물·탐험·색 변환 핵은 보존한다. 새 캐릭터·스킬·하트 폭탄·드롭 확률을 추가하지 않는다.

## 작은 설계

폭탄의 `kind`는 일반/대형 크기, `color`는 기존 공격색 0~3(불꽃·새잎·번개·물결)이다. 두 속성은 독립이다. 같은 색의 일반 패널·핵·폭탄은 실제 접촉 그래프에서 연결되며 폭탄을 경유해 계속 이어질 수 있다. 하트와 다른 색은 해당 직접 연결에 포함되지 않는다. 단독 폭탄 탭도 기존처럼 유효하다. 이는 원작 공식 확인 사항이 아닌 기존 자체 조작 규칙이다.

직접 선택한 연결 전체를 소거하며 그 안의 폭탄이 원형 폭풍을 일으킨다. 다른 색 폭탄도 폭풍에 맞으면 한 번 기폭한다. **이차 폭풍은 기존 원형 범위 판정**이다. 폭풍에 맞은 일반 패널의 동색 전체가 추가로 자동 소거되지는 않는다. 반대로 손으로 직접 고른 동색 체인은 폭풍 반경 밖까지 연결되어 있으면 포함한다. 손으로 고르는 전략을 유지한다.

폭탄 객체 자체에는 고유 공격 피해·약점 보너스가 없다. 피해/보스 공격8·약점2는 실제 제거한 일반 공격 패널만, 핵 생성/잿빛 예약은 직접 선택한 일반 공격 패널만 센다. 폭탄을 포함해 직접6개라도 일반5개면 기본6개 핵/잿빛 조건을 달성하지 않는다. 렌즈5/11은 기존대로다. 두 번째 적의 직접4 경감은 기존의 합법 직접 ID4개 규칙이므로 폭탄도 직접 대상 한 개다. 하트는 폭풍 범위에서 기존 회복2/상한/초과 구분을 따른다.

## 생성 색과 스킬

강화핵 발동 후 다음 보충 하나를 준비하는 기존 구조를 유지한다. 해당 행동에서 **처음 발동한 강화핵의 색**이 `bomb_spawn_color`가 된다. 기존 시작점 거리·ID 순서를 그대로 사용하며 여러 강화핵이 있어도 색/폭탄을 한 번만 정한다. 렌즈는 `bomb_spawn_kind`만 대형으로 만든다. 새 난수를 쓰거나 기존 첫 pending ID·공급 수·순서를 바꾸지 않는다. 물리와 색을 함께 기록하여 pending→상단 유입→낙하→정착 동안 유지한다.

Rio는 일반 패널만 대상과 경유로 사용해 변환한다. 폭탄을 변환하거나 폭탄을 경유해 스킬 대상 수를 늘리지 않는다. 변환 결과의 후속 연결 미리보기에는 이제 동색 폭탄을 포함할 수 있지만 스킬 자체는 제거/기폭/행동 충전을 하지 않는다. Noa는 폭탄에 핵을 심지 못하며 일반 패널의 원래 색으로 핵을 심는다. 번짐 안료·렌즈·잿빛의 기존 효과는 유지한다. 기존 핵의 변환도 폭탄 색을 바꾸지 않지만 범위의 기존 특수 기폭은 유지한다.

누르는 순간 위치·색·유물·전투 조건으로 같은 계획을 계산해 미리보기와 실행에 사용한다. `blasts.color`도 스냅샷에 담는다. 제거·기폭·회복은 ID마다 한 번, 새 핵과 다음 보충 폭탄은 현재 행동에서 보호한다. 취소/초점 상실/무효 입력은 행동을 쓰지 않는다.

## 표시와 실제 크기

대형은 물리·표시 반경48, 일반은 물리37이다. 동색 접촉에서 보이지 않는 간격이 생기지 않도록 일반 폭탄 표시 반경도30→37로 맞췄다. 일반 패널/폭탄 지름74, 대형96이며 SVG의 얇은 투명 여백은 같다. 기존 케이싱·퓨즈·크기 차이는 유지하고 색 테두리와 중심 속성 문양을 겹쳐 색맹/작은 창에서도 색만으로 구분하지 않게 한다. 절제 모드도 이 식별은 유지한다. 폭풍98/164는 크기와 별개이며 변경하지 않는다. 상단 유입·충돌·지지·중력·입력 좌표 변환은 바꾸지 않는다.

단일 폭탄 미리보기는 속성 이름·일반/대형·반경·전체 제거 수를 표시하고, 여러 폭탄은 횟수와98/164 범위를 구분한다. 숫자는 같은 계획에서 온다. 기존 국소 폭발 연출은 폭탄 색을 사용하며 피해를 추가하지 않는다.

## 실행한 확인

- 새 규칙 RED는 28개 중14개 실패를 확인했고 구현 후28개가 통과했다. 일반 폭탄의 시각 접촉 일치 검사는 별도로 실패를 확인한 뒤 수정했다. 추가한 직접2폭탄 중복·직접4/약점·새 코어 보호를 포함한 최종33개 체크가 통과했다.
- 기존 규칙·캐릭터·유물·전투·탐험·입력·타격·물리·중간 경로·반복 보충을 포함한51개 스크립트 실패0이다. 마지막 두 신규 케이스는 별도의33개 재검사로 확인했다. 생성 색의 pending→모든 낙하 표본→정착 유지와 새 공급 보호는 실제 main 통합11개 체크에서 통과했다.
- 기존 본체 선택15개도 일반 표시37/대형48 계약으로 재검사했다. 실제 X11 입력은720×1080,360×640,390×844에서 각각28개 체크 실패0이다. 동색 폭탄 경유로98 밖까지 이어지는 직접 연결, 다른 색 비연결, 취소, Rio 변환의 비기폭, 대형 색/164 범위/하트 회복, 절제 모드, 실제 확정 계획 일치, 리셋을 확인했다. 이 창 화면은 명시적인 접촉 fixture이며 정상 획득 증거와 다르다.
- 정상 자동 플레이는 보드·자원·체력·충전 강제 주입 없이 Noa21소거 HP30, Rio22소거 HP20으로 한 구역 승리 후 선택 복귀했다. Noa는 번개/물결 대형, Rio는 새잎 일반과 물결 대형을 실제 사용했다. 기록된 낙하 표본의 물리/표시 반경은 일반37/37·대형48/48이며 색 정보도 유지됐다.
- 독립 소스·실제 화면 검토에서 차단 사항이 없었다. 지적된 생성 색 전달과 새 코어 보호를 보완했고 작은 창의 색·문양·체인·범위 안내도 검토했다. 사람의 재미·균형·전체 영상 청취 평가는 아니다.

## 전달 자료와 한계

[소리 포함 짧은 발췌](../evidence/colored-bombs/colored-bombs-preview.mp4)는 두 정상 진행에서 가져온 편집본이다. 리오 일반 폭탄→노아 대형→리오 대형→노아 승리를 구분하며 하나의 연속 플레이로 가장하지 않는다. [노아 전체](../evidence/colored-bombs/noa-full.mp4), [리오 전체](../evidence/colored-bombs/rio-full.mp4), [검사 요약](../evidence/colored-bombs/summary.json), [독립 검토](../evidence/colored-bombs/independent-review.md)를 함께 둔다. 고정30fps MovieWriter와 오디오 존재는 실제 실시간 성능이나 청취 만족도의 증거가 아니다. 이번에는 새 실시간 A/B 측정을 하지 않았고 기존 성능 꼬리의 한계를 숨기지 않는다. 실물 기기·최종 균형·최신 Windows/Web 묶음·중단 저장/재개·임시 공용 초상은 남아 있다.

초기 RED 테스트에서 빈 확정 결과의 spawn을 직접 읽어 테스트가 중단된 기록은 `red-harness-error.log`로 보존했다. 해당 프로세스를 확인 후 종료하고 테스트의 빈 결과 접근만 고친 뒤 의도한14개 실패를 확인했다. 과거 테스트가 생성한 이전 마일스톤의 보고서는 별도 복사 후 원래 바이트로 복원했으며 현재 증거와 섞지 않았다. 처음 전체 PR connector 조회는 `Transport closed`로 실패했고 상태 확인 후 한 번의 제한된 재조회도 같은 오류여서 멈췄다. 정상 connector의 가벼운 branch Git ref/기존 exact-head workflow 조회는 성공해 기준4a500ec을 확인했다. 이전 Git/gh 인증 실패 호출이나 권한 변경은 반복하지 않았다.
