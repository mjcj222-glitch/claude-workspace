# 파괴 개수·핵 연쇄·유물 표현 보강

기준 `be5c003`에서 기존 화면/소거 표현만 보강했습니다. 물리·접촉·성장/보상 규칙, 소리와 이전 게임은 변경하지 않았습니다.

## 먼저 볼 결과

- [18.43초 소리 포함 영상](../evidence/presentation/chroma-presentation.mp4): 작은2개 소거 →38패널/핵2회 연쇄 →아이콘 보상 →보유 아이콘 설명 →최종 보드. 긴 연쇄는 연출 확인용 고정 배치임을 영상 하단에 표시했습니다. 보상2.7초·설명3초·마지막 보드1.6초를 유지하고 씬을 지운 프레임 없이 끝냅니다.
- [긴 연쇄 진행 중](../evidence/presentation/core-chain-fixture-effects.png), [유물 보상](../evidence/presentation/reward-icons.png), [보유 설명](../evidence/presentation/owned-details.png)
- 실제 [360×640 카운터](../evidence/presentation/small-360x640-window-counter.png), [390×844 설명](../evidence/presentation/small-390x844-window-owned-details.png). OS 창과 레터박스를 그대로 캡처했습니다.

영상은 Godot MovieWriter 고정30fps를 H264/AAC stereo48kHz로 인코딩한720×1140 파일입니다. 실제 게임 화면720×1080 아래60px는 고정 배치 고지입니다. 실시간 성능 근거가 아닙니다. 마지막 프레임과 비무음 오디오 트랙도 확인했습니다.

## 바뀐 표현

실행한 계획의 제거 ID와 원래 패널 ID의 교집합을 중복 제거해 큰 숫자로 올립니다. 하트와 기존 핵도 각각1개이며 새 생성 핵은 포함하지 않습니다. 끝나면 ‘합계’를 잠깐 유지합니다. ‘핵 연쇄 · N회 발동’은 실제 활성화된 핵 ID 수를 따로 세며 피해 배율을 추가하지 않습니다. 미리보기 취소·스킬 변환은 파괴 수를 올리지 않습니다.

짧은 색 파편·로컬 빛·확장 고리를 추가했고 소거 크기에 따라 양과 강도를 높였습니다. 핵은 크기/간격이 다른 세 파동을 냅니다. 최대320파편·24고리이며 긴 소거가 핵 파동을 즉시 밀어내지 않도록 핵 파동을 우선 유지합니다. 전체 화면 플래시는 사용하지 않습니다. 효과/숫자의 수명은 물리·입력 가능 상태와 독립입니다. 실제 작은 소거의 준비 상태에서도 효과가 남아 있음을 기록했습니다.

새 효과는 별도 RNG를 사용하고 기존 기본 파편의 게임 RNG 호출을 그대로 유지했습니다. 효과 때문에 보충 색이나 낙하 경로가 달라지는 것을 피합니다. 기존 소거 onset·fade·보충 시작/완료 조건도 유지합니다.

유물은 같은 금속 테두리/명암 스타일의 원본SVG 안료병·렌즈·잿빛 보석입니다. 보상 카드에100논리px, 하단88×88 터치 영역 안에78논리px로 표시합니다. 360폭에서 카드 아이콘50px·보유 아이콘39px·터치 영역44px입니다. [원본/출처/수정 기록](../assets/relics/README.md), [이3개SVG에만 적용되는CC0 고지](../assets/relics/LICENSE.txt)를 포함했습니다. 외부 그림을 복사하거나 구매하지 않았습니다.

보유 아이콘을 새로 눌렀다 같은 아이콘에서 놓으면 설명을 엽니다. 설명 내부는 보드/스킬을 막고, 닫기나 바깥의 새 입력으로 닫되 그 해제는 보드로 보내지 않습니다. 리셋은 허용하며 초점/시스템 취소·추가 손가락·오래된 해제를 처리합니다. 스킬 팔레트와 보상/요약 중 보유 아이콘 입력은 숨기거나 막습니다.

## 실제 시간 비교

Linux Godot4.6.3, Xorg/Mesa llvmpipe, MovieWriter/인코딩/다른 검사 없이 같은 시드·작은5행동·35패널/핵2개 fixture를 전후 실행했습니다. [이전](../evidence/presentation/before.json), [이후](../evidence/presentation/after.json).

| 관찰 | 이전 | 보강 후 |
| --- | --- | --- |
| 작은2~3개 소거5회 확정→해결 상태 | 635–813ms | 623–775ms |
| 35패널/핵2회 긴 소거 | 2390ms | 2382ms |
| 같은 긴 소거 낙하 시뮬레이션 | 1.766667초 | 1.766667초 |

작은 차이는 단일 실행의 변동 범위이며 성능 향상으로 주장하지 않습니다. `next_phase=reward`는 보상이 열린 시점으로 사람의 선택 대기는 포함하지 않습니다. 긴 연쇄는 여전히2초 이상이고 모든 소거/장치에서1초 이하를 보장하지 않습니다.

## 검증과 한계

- 피드백32검사: 하트, 여러 핵, 중복 도달·생존/미존재ID 제외, 새 행동/리셋, 정산·시간 종료, 효과 예산·핵 파동 우선순위.
- 실제 씬32검사: 실제 규칙 미리보기=실행, 하트/핵2회·중복 이벤트·새 핵 보호, 취소·스킬·리셋, 기존 RNG 소비량 유지.
- 보유 설명36검사: 새 입력 소유권, 영역 이탈·초점·시스템 취소, 추가 손가락, 내부/외부/닫기 해제 관통 방지, 보드 선택 보존, 스킬·보상·요약·리셋과의 관계.
- 기존 규칙44·유물64·성장/보상 입력·실제 씬·긴 연출·중간 경로·10회 반복 보충·상단 걸림 스냅샷 회귀를 다시 실행했습니다. 결과는 `evidence/presentation/regression-*.log`와 `motion-audit.log`입니다. 현재 화면에서 안료+렌즈 정상9회 흐름을 `play-pair0.json`으로 재검증했고 통과했습니다. 다른 두 조합의 기존 정상 진행 자료는 이전 성장 커밋에 있으며 이번에 새로 완주했다고 표시하지 않습니다.
- 두 작은 실제 X11 창에서 보상/보유 설명/리셋/스킬과 실제 초기 보드2개 소거 카운트를 OS 마우스로 검사했습니다. 보상 상태는 입력 검사용 fixture이며 정상9회 증거와 구분합니다.
- 독립 코드·작은 창 화면 검토에서 차단 결함은 발견하지 않았습니다. 첫 쇼케이스 정지 화면이 상태 변경 전 프레임을 잡는 문제는 다음 process/draw를 기다려 수정했습니다.

소리 포함 영상·수치/입력 검사와 주관적 화려함/재미는 별도입니다. 실물 Android/Windows/Web, 모바일 GPU·터치 지연과 실제 스피커 청취는 검증하지 않았습니다. 기존 ZIP은 이번 소스가 아닙니다. Library 전달은 부모가 담당합니다.
