# 속성 약점·마지막 전투 연결 준비

기준: 로컬/원격 `f2d7cd1be792da888d72350dc747229b2ebef664`, 작업 트리 깨끗함 확인. 기존 세 전투/경로/골드/상점/유물/접촉·중력과 보류된 UI·폰트 우선순위를 유지합니다. 이번 목표는 초반에는 약점을 배우고 마지막에는 예고를 보고 계획하는 작은 전투 확장입니다. 정확한 약점 배치·피해 계수·마지막 패턴은 부모 계약 수신 전 확정하지 않습니다. 새 아트·긴 지도·추가 화폐/콘텐츠는 제외합니다.

## 실제 소스에서 확인한 연결 지점

- `board_rules.gd::plan()`은 같은 접촉 스냅샷 위에서 직접 묶음→기존 핵 변환/연쇄→고유 제거ID를 계산합니다. 내부 `colors`는 변환 후 실제 색을 보유합니다. 현재 피해는 제거된 `normal`당1, 하트는2회복, 기존 핵 자체는0피해입니다. 새 약점 산술은 이 고유ID/유효색을 사용해야 합니다. 핵 생성 기준/Ash의 직접 일반 개수와 피해 보너스를 혼동하지 않습니다.
- `board_session.gd::begin()`은 `plan_for()` 결과를 선택에 저장하고 `release()`는 같은 계획을 복제해 피해합·회복·충전·예약을 반영합니다. `board_run_session.gd::release()`와Combat도 그 결과를 사용합니다. 적 단계에서 나중에 피해만 다시 바꾸면 화면/누적합/실행이 달라지므로 피합니다.
- `board_run_session.gd`의 `plan_for()` 연결에서 적의 순수 값 context를 전달하고, 필요하면 Rules.plan에 기본값 있는 context인수를 추가하는 접근이 작습니다. 실제 계획은 보드·유물·적context를 누름 시점 값으로 고정하며 live 적 객체를 참조하지 않습니다. 기존 sandbox와 순수 기본 규칙의 피해는 기본 context로 보존할 수 있습니다.
- `board_combat.gd::prepare_turn()`은 실제 시작 보드를 검사하고 `_turn_prepared`로 같은 턴의 예고/기회를 고정합니다. `record_clear()`는 직접 고유ID 조건을 판정하며 처치→반격 우선순위를 유지합니다. 마지막 예고도 승인 계약의 실현 가능한 조건만 이 경계에서 준비할 수 있습니다.
- `board_ui.gd`는 저장된 selection의 피해/회복과Combat의 예고를 표시합니다. 약점·조건 진행과 피해 내역은 이 값들로 표시하고 버튼이나 UI에서 별도 피해를 재계산하지 않습니다. 기존 작은 화면·판정 좌표와 보이는 패널 영역을 유지합니다.

## 계약 수신 후 작은 실행 순서

1. 고유 일반ID/유효색별 약점 피해, 핵 변환·충돌 순서·중복/하트/핵 제외, 미리보기와 실행 일치부터 결정적 테스트로 고정합니다. 계약의 정확한 색/계수/대상만 사용합니다.
2. 적별 약점과 마지막 예고/기회·진행/성공·실패·fallback·단계 전환을 기존 세션에 연결합니다. 스킬/무효/취소가 행동을 소비하지 않으며 경로·상점·유물·재시작의 기존 불변식을 유지합니다.
3. 실제 보드에서 양경로·유물 조합 정상 진행과 작은 창 입력/표시를 확인하고 기존 규칙·성장·경제·접촉·중간 경로/반복 보충 회귀를 실행합니다. 독립 검토, 읽을 수 있는 소리 영상, 실제 벽시계와 고정 녹화의 분리 기록 후 PR3만 저장합니다.

이 문서는 계약 수신 전 준비 기록입니다. 이후 승인 계약에 따라 구현·검증했으며 [실행 계획](ELEMENTAL_PLAN.md)과 [최종 결과·증거](ELEMENTAL.md)를 확인하세요.
