# 대형 폭탄의 실제 부피

기준 2b32d639. 사용자 요청은 외형 확대를 넘어 실제 공간 점유·접촉·낙하 확대다. 대형의 물리 반경을 37에서 48 논리 px로 바꿔 현재 96 px 외형과 맞춘다. 일반 패널·일반 폭탄의 물리 반경은 기존 37이다. 일반 폭탄 표시 반경 30, 대형 표시 반경 48을 유지한다. 폭풍 반경 98/164는 물체 반경과 별도이며 변경하지 않는다. 이 숫자는 원작 수치가 아니라 프로토타입 가설이다.

공급 때 기존 첫 pending 물체의 ID·수·난수 소비를 유지하면서 대형의 반경도 48로 설정한다. 상단 유입의 좌우 여유, 시작 높이, 현재 표면의 통과·정착 여유를 다음 물체의 실제 반경으로 계산한다. 기존 충돌·지지·벽·접촉 그래프는 이미 각 반경의 합을 사용한다. 물리 경로, 중력 계수, 준비 기준과 4초 실패 제한은 바꾸지 않는다. 공간이 부족한 상태를 억지로 준비 처리하거나 몸체를 재배치하지 않는다. 반경을 바꾼 뒤의 보충과 연결 결과는 이전 버전과 달라질 수 있다.

## 일반 폭탄과 공식 근거

현재 구현은 무속성이다. 강화핵을 실제 발동하면 다음 보충에 일반 폭탄 하나를 준비하며, 렌즈 소유 시 대형 하나가 된다. 긴 연결 자체에 폭탄을 중복 지급하지 않는다. 단독 탭, 다른 폭탄의 폭풍, 핵의 접촉 범위로 기폭한다. 같은 색 일반 연결의 대상·경유와 스킬 변환 대상에서는 제외한다. 주변 패널은 행동 시작의 중심점 거리로 판정한다. 하트는 회복, 일반은 기존 피해·약점, 핵과 폭탄은 중복 없는 연쇄를 적용한다. 새 보충은 현재 행동에 자동 합류하지 않는다. 색상 값 0은 기존 내부 자리값이며 빨강 속성 공격을 뜻하지 않는다. 선택 안내에 무속성과 폭풍 반경을 분명히 표시한다.

2026-10-21 직접 읽은 [공식 패널 FAQ](https://crashfever.com/faq/2025070141778/)는 SCP 파괴 및 스킬의 폭탄 생성, 주변 파괴, SCP 기원 폭탄의 별도 취급을 설명한다. [공식 유닛 공지](https://crashfever.com/unit-syuusei20180221/)에는 파랑·하트·5색 폭탄, 대/특대와 폭풍 강화가 별도로 나온다. 이는 색 폭탄의 존재 근거이지 우리 무속성 폭탄·단독 탭·동색 연결 제외가 원작과 같다는 근거가 아니다. 해당 세부와 정확한 물리/폭풍 반경은 공식 확인되지 않았다. 근거 없이 색 연결 규칙을 바꾸거나 내부 0을 빨강으로 표시하지 않는다. 색 폭탄의 별도 생성 및 동색 연동은 후속 검토 사항이다. 최초 구 FAQ 직접 열기는 도구에서 접근 불가였고, 새 공식 FAQ는 정상 읽었다.

## 검증 계획

공급 반경, 표시 이중 확대 방지, 가변 반경 유입, 벽·바닥, 접촉 거리, 6개 대형 밀집과 중간 경로, 기존 규칙·탐험·전투 회귀, 세 창 크기의 실제 입력, 두 캐릭터 정상 승패를 확인한다. 영상은 고정 프레임 증거와 실시간 측정을 분리한다. 원래 정상 보드의 과거 경로를 동일하다고 주장하지 않고, 동일 공급으로 크기가 바뀐 결과를 비교한다.

## 확인한 결과

- 대형 6개와 일반 42개를 빈 보드 위에서 순서대로 공급한 실제 시뮬레이션은 2.242 sim초에 정착했다. 최대 중간/선분 최소거리 겹침은 약 0.135 px, 한 tick 최대 이동은 9.167 px다. 이는 기록된 fixture의 허용 오차 내 수치이며 임의 재배치나 완전 무오차를 주장하지 않는다.
- 혼합 생존체 보충 및 지지 상실 59개 체크가 통과했다. 실제 대형 ID49를 지지한 ID41만 제거하자 같은 몸체가 약 8.33 px 내려왔고, 모든 정착 몸체는 아래 접촉을 통해 바닥으로 연결됐다. 해당 두 경로의 최대/swept 겹침은 0.029 px 미만, 무접촉 횡속도 주입은 0이었다.
- 기존 회귀 포함 49개 스크립트 실패 0. 물리 계약이 달라진 공급 기대값과 큰 몸체 fixture 반경은 48로 갱신했으며 폭풍 98/164를 별도로 검사한다. 최종 폭탄 규칙 27개 재검사도 통과했다. 과거 보고서 파일은 그대로 보존하고 새 결과만 별도 기록했다.
- 실제 X11 입력은 720×1080, 360×640, 390×844에서 각각 23개 체크 실패 0이다. 실제 정착한 대형 6개와 일반 폭탄 1개를 포함한 고정 배치 fixture이며 정상 획득 증거와 구분한다. 반경 37~48의 테두리, 벽 안/밖, 취소, 미리보기/실행, 절제 모드, 리셋을 확인했다. 이전 본체 검사도 물리 48 fixture로 통과하여 확대율 0.5/1/1.25 역변환을 확인했다.
- 중간 자원·충전·체력·보드 주입 없는 정상 자동 진행: 노아 21소거 HP30 승리, 리오 유료 이벤트 19소거 HP30 승리, 리오 무료 이벤트 23소거 HP20 승리. 일반 폭탄과 대형 모두 등장했고, 대형 낙하 기록은 물리/표시 48/48이었다. 두 캐릭터의 최소 소거 위주 attrition 정책은 각각 20소거 HP0 패배 후 선택으로 복귀했다. 이 정책은 사람의 실력 모델이 아니다.
- 독립 검토의 혼합 생존체·지지 경로 공백을 보완했고 최종 소스·실제 이미지 검토에서 차단 사항은 없었다. 전체 영상 청취 평가는 하지 않았다.

## 실시간 측정과 한계

같은 클라우드 native llvmpipe에서 이전 2b32d63과 수정 소스에 동일한 측정 래퍼를 넣은 격리 복사본을 사용했다. 정상 사전 기록 입력 7회를 A–B–B–A–A–B 순서로 버전별 3번 재생했다. 이 구간에는 정책 탐색·스크린샷·파일 출력이 없고 다른 테스트/녹화 프로세스도 실행하지 않았다. 앞선 탐색 측정 6개에는 아티팩트 probe/최종 단위 검사가 겹쳤으므로 원본을 보존하되 `clean-` 측정과 섞지 않았다. 수치가 나빠서 제외한 것이 아니며 깨끗한 블록 전체를 보고한다.

`commit_to_ready`라는 기존 이벤트 이름은 일부 행동에서 `enemy_attack` 또는 `reward`가 다음 상태다. 위 보충 완료 수치가 모든 경우에 반격 후 다음 입력까지의 시간이라는 뜻은 아니다. 7번째 행에는 예고된 반격까지 포함한 별도 완료 벽시계를 썼다. 낙하 CPU 합은 anchor/spawn/solve 내부 타이머이며 벽시계·시뮬레이션 시간과 구별한다. frame process monitor에는 대기/프레임 비용도 섞이므로 draw 래퍼 CPU와 같은 의미로 해석하지 않는다. Compatibility 소프트웨어 렌더러의 GPU 수치는 신뢰 가능한 별도 기기 벤치마크가 아니다.

세 쌍의 7개 소거 계획이 모두 같았고, 첫 6개 결과 상태도 같았다. 7번째 공급에서는 큰 반경 때문에 물리 배치가 의도대로 달라졌다. 따라서 마지막 수치는 순수 렌더 성능 비교가 아니며 이후 보드/정책 결과가 같다고 주장하지 않는다. 폭탄 없는 기존 2개 제거·중앙·왼쪽 제거의 중간 좌표 기록은 이전과 정확히 같았다. 표본이 작고 분포가 겹쳐 성능 개선이나 완전한 동등을 단정하지 않는다. 수정 쪽에도 일반 소거 1.0초 초과 관측이 남아 있다.

원본은 `evidence/bomb-volume/performance/`, 요약은 [performance-summary.json](../evidence/bomb-volume/performance-summary.json)이다. Android/Windows 실물 입력·스피커/헤드폰 청취, 사람의 재미와 최종 균형은 미검증이다. 최신 실행 ZIP, 중단 저장/재개, 임시 공용 초상 문제도 이번에 해결하지 않았다. 실패한 초상 전달과 Windows 다운로드는 재시도하지 않았다.

실패/수정 기록: 새 부피 검사에서 실제 반경·이중 표시 확대·대형 반경 유지의 세 실패를 먼저 확인한 뒤 같은 검사 13개가 통과했다. 초기 git 상태 조회는 `/workspace`가 저장소가 아니어서 실패해 보존된 작업 트리 경로에서 재조회했다. 존재하지 않는 과거 문서/측정 경로 조회와 복수 로그 tail 문법 오류는 읽기 단계 실패였고, 실제 파일 목록에서 현재 경로를 확인했다. 보호된 `/tmp` 하위 디렉터리의 광범위 파일 검색은 접근 불가였으며 그 경로를 우회하거나 재시도하지 않았다. 작업 파일·녹화·저장은 별도 허용 경로에서 계속했다. 남은 권한 차단은 없다.
