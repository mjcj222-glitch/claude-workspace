# 새 탐험과 로컬 이어하기

2026-10-22. 기준 후보 `767f87a`에서 이어진 소스 변경입니다. 기존 Windows/Linux Library 후보는 그대로이며 이 기능을 포함하지 않습니다. 설계는 [RUN_LIFECYCLE_DESIGN.md](RUN_LIFECYCLE_DESIGN.md)에 먼저 기록했습니다.

## 동작

정상 새 탐험은 새 시드를 선택합니다. 진행 저장이 있으면 시작 화면에 **이어하기 / 새 탐험**이 나타납니다. 새 탐험이나 진행 중 리셋은 확인을 거쳐 이전 저장 폴더를 보관한 뒤 시작합니다. 취소하면 현재 탐험/저장을 유지합니다. 정상 게임 실행에는 계정·네트워크·외부 전송이 없습니다.

출발, 지도 선택/입장, 보상·상점·휴식·이벤트 거래, 확정된 스킬, 소거 후 낙하와 적 반격이 끝난 상태를 저장합니다. **연쇄·낙하·반격 도중 종료하면 마지막 완료 시점부터 다시 진행합니다.** 누른 채인 입력·미리보기·진행 중 애니메이션은 저장하지 않습니다. 재개 후 새로 눌러야 행동이 시작됩니다.

시드와 두 RNG 상태, 캐릭터, 패널 고유 ID/위치/색/종류/반경과 next_id, 스킬·충전·생명·골드·유물, 지도/방문/지급 기록, 보상 후보·상점 재고·거래 serial, 적 의도와 정산 가드를 복원합니다. 적 의도나 보드를 재추첨하지 않습니다. 음소거·효과 감소 설정도 함께 복구합니다. 전투 수치·물리·폭탄 외형·타격 효과 구현은 변경하지 않았습니다.

## 파일과 복구

기본 위치는 Godot `user://chroma-checkpoint/`입니다. 버전1 envelope에 크기 제한, SHA256, 객체를 허용하지 않는 Variant 해석, 명시적 필드/타입/범위/ID/지도 경로/진행 일관성 검증을 적용합니다. 정수 RNG 상태와 Vector2를 손실 없이 보관합니다. 현재 파일은 임시 파일의 쓰기·flush·검증 후 같은 파일시스템에서 교체하며, 유효한 직전 상태를 backup으로 유지합니다.

현재 파일이 손상되면 유효한 backup의 복구임을 화면에 표시합니다. 손상된 원본은 읽기만으로 지우지 않으며, 복구 후 다음 저장 때 별도 보관합니다. 둘 다 읽을 수 없거나 호환되지 않으면 임의 보상/상태를 만들지 않습니다. 새 탐험을 확인하면 이전 폴더 전체를 archive로 보관합니다. 저장 쓰기 실패는 화면에 표시하고 이전 체크포인트를 유지합니다.

승패가 끝나면 별도 완료 장벽을 먼저 기록합니다. 장벽이 있으면 이전 backup도 이어하기 대상으로 쓰지 않습니다. 장벽 손상도 보수적으로 재개를 차단합니다. 파일시스템 쓰기 자체가 실패한 경우 성공했다고 표시하지 않습니다. 디스크 전원차단 내구성/fsync, 동시 여러 게임 인스턴스의 쓰기 경쟁, 수동 파일 편집에 대한 부정행위 방지는 보장하지 않습니다.

## 재현 옵션과 테스트 격리

- `-- --seed=20261021`: 새 탐험·리셋의 명시적 고정 시드. 이어하기에서는 저장된 시드가 우선합니다.
- `-- --no-save`: 읽기/쓰기와 이어하기 UI를 비활성화합니다. sandbox와 short-run도 저장 대상이 아닙니다.
- `-- --save-dir=/tmp/chroma-test-고유경로`: 저장 검사용 별도 폴더. 일반 테스트는 `--seed=20261021 --no-save`를 씁니다.
- `--script` 진단 실행은 별도 `--save-dir`가 없으면 저장하지 않습니다. 일반 사용자의 데이터와 테스트가 섞이지 않게 했습니다.

## 초기 실패와 남은 한계

첫 소거 뒤 스키마가 물리 엔진의 StringName 키를 거부했습니다. 허용되는 기본 타입에 이를 추가했고 실제 소거/재개로 재검증했습니다. 첫 headless 프로세스 검사에는 상속된 화면 캡처가 남아 대기했으므로 해당 검사에서만 캡처를 제거했습니다. 일반 창 검사는 화면이 뜨기 전 클릭한 준비 조건 오류가 있었으며, 실제 헤더가 나타난 뒤 입력하도록 수정했습니다. 게임 시작이 순간적이거나 특정 성능을 보장한다고 주장하지 않습니다.

새 고정-FPS/Dummy 오디오 프로세스 검사 일부는 종료 시 AudioStreamPlaybackWAV/ObjectDB 경고가 남습니다. 대기 및 정지/프레임 정리 probe에서도 재현되어 해결했다고 주장하지 않습니다. 이 경고와 무관하게 저장 상태 assertion은 통과했지만 모든 오디오 종료 경로의 무누수를 검증한 것은 아닙니다. 기존 `test_impact_strength`를 포함한52개 회귀 결과와 구분합니다. 음향·이펙트 코드는 바꾸지 않았습니다.

Windows/모바일 저장 실행, 실물 음향, 전원 차단 중 파일시스템 내구성, 동시 다중 인스턴스, 모든 무작위 시드/희귀 보드는 미검증입니다. 서버 저장·계정·동기화·다중 슬롯·영구 성장 저장은 포함하지 않습니다. 기존 후보 ZIP을 새 기능이 있는 것처럼 교체하지 않았습니다. 최신 승인 범위의 기존 PR3 푸시·자동 preview 외 수동 배포/설정 변경은 하지 않습니다.
