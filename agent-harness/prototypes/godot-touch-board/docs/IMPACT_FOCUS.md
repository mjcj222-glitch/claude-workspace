# 소거·폭탄·명중의 시간 대비

2026-10-22. 기준 `b4186b4fd0c4680086efe190f67eecd836131470`, PR #3의 같은 프로토타입만 수정한다.

## 진단과 작은 설계

기존 일반 소거음은85ms이며 연쇄 onset 간격은 대략7~32ms다. 네 pop voice가 겹치고, 핵·폭탄은 같은 다섯 번째 voice를 매번 다시 시작한다. 따라서 뒤따른 약한 핵이 더 긴 폭탄 어택을 끊을 수 있다. 적 명중은 이미 소거 완료/낙하 시작과 같은 한 번의 이벤트로 음향·표시 체력·국소 반응을 동기화하고 있어 그 시점은 유지한다. 폭탄의 세 후속 파동은 시작 지연과 수명을 합쳐 최대0.70초 남는다. 합계 HUD는 모든 패널마다 같은 크기로 뛰고 완료 순간은 오히려 약하다.

설계는 새 시스템이나 더 큰 마스터 음량 대신 강한 사건 전후의 대비를 정리하는 것이다. 일반 소거·완료 음을 잠깐 비워 폭탄/명중의 어택을 드러내고, 폭탄 잔상을 짧게 닫으며, 카운터는 묶음/완료 때 강조한다. 더 명확하게 느껴질 것이라는 표현상의 가설이며 사람의 청취/재미 평가를 완료했다는 뜻은 아니다.

## 구현 범위

- `board_audio.gd`: 기존 네 pop voice를 핵·폭탄·명중 시 최대6dB 낮춘다. 80ms 유지 후80ms 복귀, 전체160ms다. 새 소리도 같은 감쇠를 따른다. 핵/강화핵/일반폭탄/대형폭탄 순의 우선순위로 재생 중인 강한 특수음을 약하거나 같은 등급의 후속음이 끊지 않는다. 더 큰 폭탄은 즉시 교체한다. 생략된 음을 나중에 큐로 재생하지 않는다.
- 기존 PCM·pitch·voice 수6개·특수음−13dB·명중−8dB·마스터 gain은 그대로다. 감쇠는 일반 소거/완료/착지 voice에만 적용한다. 명중은 원래 전용 voice로 원래 시점에 재생한다.
- `board_feedback.gd`: 폭탄은 소거 사건과 동시에 시작하는0.20초 주 파동과60ms 뒤 시작하는0.26초 보조 파동을 사용한다. 최대 끝점은0.32초, 폭탄 조각 수명은0.18~0.36초다. 핵의 기존 세 파동·입자/링 예산320/24는 유지한다. 새 화면 전체 플래시는 없다.
- 일반 count는 약한 강조,4개마다 중간 강조,핵·폭탄·완료 때 강한 강조다. 숫자는 실제 소비 ID만 세며 새 combo 배율을 만들지 않는다. 절제 모드에서는 새 숫자 크기 변화도 멈춘다.
- `main.gd`: 기존 reset의 voice 정지 부분만 명시적 오디오 reset으로 바꾸어 남은 감쇠·우선순위도 지운다. 입력·계획·소거 schedule·게임 RNG·명중 시점·낙하·전투 수치는 바꾸지 않는다.

원판 아트, 일반/대형 물리37/48와 폭풍98/164, 생성색·접촉 연결, Rio/Noa·유물·진행 밸런스는 그대로다.

## 검증 증거

- `test_impact_focus.gd`: 이전 소스에서14개 중9개 의도된 실패, 구현 뒤17개 통과. 기존 pop과 새 pop 감쇠, 약한 핵의 폭탄음 방해 금지, 기존 명중 gain, 복귀·mute·reset, 파동 시작/종료·예산·완료 중복을 검사한다.
- 기존51개+신규1개 총52개 회귀 스크립트 실패0. 로그와 생성된 물리 trace는 `evidence/impact-focus/regression/`, `new-motion-regressions/`. 이전 milestone 파일은 검사 후 원래 바이트로 복원했다.
- 별도 실제 controller 검사6개 통과: 앱 초점 상실 취소, busy 중10회 반복 입력, 한 번의 명중, 명중 중reset, 이전 효과 재발 금지, mute 보존.
- 정상 Rio 전후는 이번에 기준/수정 소스로 각각 실제 녹화했다. 둘 다22소거 HP20 승리. Noa 수정 실행은21소거 HP30 승리, 변경 없는 기준 커밋의 이전 녹화 trace와 비교했다. 두 캐릭터 총184개 이벤트의 보드·계획·전투 상태, 최종 상태, 명중 이벤트, 보충 완료 프레임 수가 같다. 비교에서 제외한 상태 필드는 `wall_ms`, `process_frame`, `scene_seconds`뿐이다. [상태 결과](../evidence/impact-focus/state-comparison.json).
- 전체 두 영상과 미리보기 세 영상의 디코딩 float PCM에서 클리핑/NaN/Inf 샘플0, 모두 비무음. 전체 이전/수정 peak는 약−9.29/−9.62dBFS, RMS는−32.38/−32.57dBFS다. 강하게 만들기 위해 전체 gain을 높인 변경이 아니다. [음향 검사](../evidence/impact-focus/audio-validation.json).
- 하네스 구성 검사/Python5개와 GitHub의 Agent Harness Sanity Check는 Godot 검증과 별개다. CI 자체가 Godot 실행을 검사한다고 주장하지 않는다.

## 실패 및 한계

- 추가 scene 검사 초안이 실제 구현의 APPLICATION_FOCUS_OUT 대신 WM_WINDOW_FOCUS_OUT을 호출해2개 실패했다. 알림을 바로잡아6개 통과했으며 최초 로그를 보존했다.
- 과거 `capture_quality_states.gd`의 전투 즉시복귀·과거 경로·코어 fixture 기대값5개가 현재 게임과 맞지 않아 세 창에서 실패했다. 변경 전 b4186b4의360×640에서도 동일5개 실패를 재현했다. 기존 도구를 통과했다고 하지 않으며 게임 규칙을 바꿔 맞추지 않았다. 현재 계약을 쓰는 별도 창 검사를 사용한다.
- 새 창 검사 초안의 마지막 assertion이 해제한 scene을 읽어 중단되었다. 로그 보존 후 driver를 중단하고 assertion을 해제 전에 옮겼다. 이는 검사 코드만의 수정이다.
- Library 지원 배치 업로드 helper는 파일 전송 전 앱 목록 조회에서 `network` 오류로 종료했다. 새 Library 파일/ID/버전은 생성 확인되지 않았으며 직접 업로드로 바꾸지 않았다. PR 자료는 별도로 보존한다.
- cloud Linux/Godot4.6.3/Xorg/llvmpipe/Dummy audio 환경이다. 사람의 실제 청취, 실물 터치·스피커, Android/Windows/Web 빌드, 주관적 손맛/재미는 미검증이다. 병합·배포·계정 변경은 하지 않는다.

## 현재 창·실시간 확인

현재 계약 창 검사는360×640,390×844,720×1080 각각39개 실패0이다. 실제 OS 입력으로 동색 연결/미리보기/취소, busy 중 반복 클릭, 절제 전환, 명중 중 mute/reset을 확인했다. 구성한 접촉 fixture이며 정상 획득 증거와 구분한다. `windows-current/`는 최종 결과, `windows/`와 `legacy-window-before.log`는 과거 도구의 불일치 기록이다.

기록된 동일 Noa8행동을 A–B–B–A 순서로 직렬 재생했다. 정책 탐색·캡처·파일 출력은 측정 구간 밖이고 검사/녹화/인코딩과 겹치지 않았다. 각 행동의 계획·정착 보드·RNG 상태가 네 실행 모두 같았다.

입력→첫 draw 중앙값은 이전16.81ms/수정16.13ms, 최대는21.64/20.85ms다. 반격까지 포함한 해결 중앙값은1259.9/1270.9ms, 최대2558.9/2554.6ms다. 보충 완료만의 중앙값은1068.9/1086.8ms다. 작은 표본으로 성능 개선이나 모든 입력의 지연 보장을 주장하지 않는다. 2초 이상 반격 포함 꼬리도 남아 있다. [전체 요약](../evidence/impact-focus/performance-summary.json)과 원시performance JSON을 보존한다.

캡처 중 일부 중복 화면은 로컬에만 보관하고 `capture-manifest.json`에 목록을 남겼다. 초기 전후 영상의 stream-copy 연결은 AAC 경계 DTS 경고가 나와 로그를 보존하고 각11.6초 오디오/영상의 타임스탬프를 재설정해 재인코딩했다. 최종23.2초 파일을 다시 음향 검사했다.
