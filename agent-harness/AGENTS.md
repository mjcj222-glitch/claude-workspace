# Agent Harness 작업 규칙

## 미션
`agent-harness/topics.json`의 활성 목표를 분해하여 **조사 → 검증 → 구현(필요 시) → 보고 → 다음 과제** 순환을 수행한다. 총괄은 dot 또는 사람이 맡는다. 독립 에이전트 지원 여부가 명확하지 않으면 역할별 순차 패스로 수행한다.

## 작업 전에
1. 이 문서와 `agent-harness/README.md`, `agent-harness/topics.json`을 읽는다.
2. 요청한 역할에 맞춰 `agent-harness/roles/`의 해당 문서를 읽는다.
3. 보고 결과는 `agent-harness/reports/YYYY-MM-DD/` 아래 Markdown으로 정리한다. 비공개 자료는 공개 GitHub에 업로드하지 않는다.

## 증거와 품질
- 최신 정보는 검색 날짜, 자료 날짜, 원문 URL을 포함하고 가능한 한 1차 출처를 사용한다.
- 사실/가설/의견, 반증, 미확인 사항을 분리한다.
- 새로운 내용을 찾지 못하면 '변화 없음'으로 보고한다. 없는 소스나 실행 결과를 만들지 않는다.
- 실패한 명령어·테스트도 실행 환경과 함께 기록한다.
- 다음 과제는 최대 3개만 선정하고 중복 조사를 피한다.

## 권한과 예산
- 프로젝트 기본 작업 범위: `agent-harness/` 아래 파일. 다른 디렉터리 변경 전 승인 요청.
- 비용이 생기는 API·서버·구독·크레딧 구매 금지. Pro 포함 사용량 우선, 한도에 도달하면 중단한다.
- 로그인 쿠키, 토큰, API 키, 비밀번호, 2FA 코드 등을 요구하거나 소스에 저장하지 않는다.
- 보안 설정 완화, 외부 전송, 배포, 대량 삭제 및 기존 저장소 코드 변경은 먼저 승인.
- 기존 파일과 히스토리를 무단 덮어쓰지 말고 영향이 있으면 PR로 제안한다.
- 정기 실행은 dot의 공식 예약 기능을 사용한다. GitHub Actions에 ChatGPT 세션을 넣어 'API 무료 우회'를 시도하지 않는다.

## 역할/출력
- Research: `roles/research.md`
- Verify: `roles/verify.md`
- Build: `roles/build.md`
- Report: `roles/report.md`
- 날짜별 보고서 형식: `reports/REPORT_TEMPLATE.md`

## 완료 조건
요구사항·검증 근거·수행한 테스트·변경 파일·남은 질문이 모두 보고되어야 완료다. **프롬프트 작성, 사용자 승인 대기, 실제 실행 성공**을 혼동하지 말 것.
